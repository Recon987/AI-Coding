# TASK-UX-03 — 세 분야 협의 개선 루프

사용자가 세 분야의 전문가 역할 에이전트가 서로 협의하는 개선 루프를 요청했다. 이번에는 같은 자료로 독립 검토 → 직접 협의 → 구현 → 상대 분야의 교차 검토 → 보완 → 실제 검증을 한 차례 완료했다. 배경에서 계속 실행되는 자동 개선 서비스는 아니다.

## 역할과 협의 결과

| 역할 | 최초 제안·발견 | 상대 의견과 합의 | 구현·교차 검토 |
| --- | --- | --- | --- |
| ux_expert: 업무 UX·정보 구조 | 첫 화면에 다섯 빈 영역이 동시에 노출되어 시작 행동이 분산됨. 날짜와 선택일 맥락 부족 | 완전 빈 자료에서만 시작 화면을 표시. 완료 기록·메모·조직 정보가 있으면 기존 브리핑 유지. 버튼은 실제 도착점에 맞춰 '근무현황판 준비'로 표현 | Briefing·공통 날짜 구현. 시각 담당이 코드를 확인하고 품질 담당이 동작·보존 검증 |
| visual_expert: 시각 디자인 | 달력 유형 접두어가 제목 폭을 차지하고 범례와 상세 태그 색이 다름 | 유형을 아이콘과 범례로 구별하고 색만 의미하지 않도록 함. 제목 공간을 넓히되 선택 날짜 전체 목록 유지 | Calendar·CSS 구현. UX 담당이 1280/960 화면을 독립 검토하고 승인 |
| quality_expert: 품질·접근성 | 날짜 버튼의 명시적 접근 이름이 하위 기록 제목을 가림. 기존 배치 검사는 실제 첫 행동을 보장하지 않음 | 날짜 버튼 이름에 표시 3건의 유형·시각·전체 제목과 추가 건수를 포함. 전체 기록은 선택 목록에서 제공. CTA 이름과 설명을 분리 | format·UI·Electron 회귀 작성. 시각/UX 제안을 교차 검토하고 승인 |

모든 기록을 날짜 버튼 이름에 붙이는 안은 이름이 지나치게 길어질 수 있어 표시 3건과 나머지 건수, 선택 목록 전체 접근으로 조정했다. 960px 첫 화면의 행동이 접힐 우려는 실제 CSS와 캡처로 확인했다. 세 행동 모두 화면 안에 보이고 설명은 줄바꿈된다.

## 구현 후 발견과 보완

첫 캡처 검증에서 시작 버튼의 설명 문구까지 접근 이름에 포함되어 정확한 행동 이름으로 찾지 못했다. 제목은 aria-labelledby, 설명은 aria-describedby로 분리하고 재검증했다. 토요일 공휴일이 일반 토요일의 파란색에 덮일 수 있는 우선순위도 수정하고 개천절 경계 검사를 추가했다. 최종 캡처는 두 보완 이후 소스로 생성했다.

공통 읽기 날짜는 `2026. 10. 15. (목)`, 시각은 `08:00`, 날짜·시각은 `2026. 10. 15. 08:00`이다. 날짜만 있는 YYYY-MM-DD는 UTC 시점으로 바꾸지 않고 PC 현지 달력일로 해석한다. native 날짜 입력은 OS 위젯을 유지한다. 화면과 TXT에 같은 시각 포맷을 사용하며 저장 ISO 값·자료 v3·기존 원본 참조·트레이는 유지했다.

## 전후 비교

| 항목 | 개선 전 | 개선 후 |
| --- | --- | --- |
| 완전 빈 홈 | 업무·날짜·근무·전화·메모의 빈 상태 분산 | 시작 안내 1개, 실제 시작 행동 3개, 기존 빈 카드 0개 |
| 1280px 달력 영역 | 약 637px | 약 699px. 제목 공간 증가 |
| 칩 정보 | 유형 접두어 때문에 제목이 짧게 생략 | 유형 아이콘+제목, 전체 제목/24h 시각 tooltip |
| 선택일 상세 | 연도·요일 없음, 오전/오후 시각 | 연도·요일과 24h 시각, 범례와 일치한 유형 |
| 날짜 버튼 접근 이름 | 날짜·건수 | 날짜·공휴일·유형·시간·전체 제목(표시 3건)+나머지 건수 |

폭 수치는 고정 1280×800 실제 캡처를 읽은 근사치이며 미적 품질 점수는 아니다. 선택일 영역이 줄어 긴 제목의 줄 수는 늘 수 있다. 월간 칩의 긴 제목은 여전히 생략되며 tooltip과 선택 목록에서 전체를 읽는다.

## 검증과 재현

- npm test: 37/37. 신규 날짜 검사는 서울·뉴욕 자식 프로세스에서 연말·윤일·00:00·현지 변환·잘못된 날짜를 검증한다.
- npm run test:desktop: 통과. 첫 사용 세 행동, 실제 편집창·현황판 도착, 자료 불변, 메모 1건/완료 일정/직원 자료 보존, 달력 접근 이름과 기존 업무·좌표·백업·트레이 회귀를 실행했다.
- UI: 기존 before 83개와 확장 after 134개 검사 각각 통과. 1280×800, 1360×900, 960×680, 125% 확대. 페이지 오류 0, 외부 요청 0.
- 가상 자료와 임시 프로필만 사용했다. OS 알림·확인 UI는 기존 테스트 대역이다. Linux 실제 Tray 표시는 미실행이며 Windows 검증과 구분한다.

```sh
npm run build
PARK_REVIEW_STAGE=loop3-after PARK_REVIEW_ZOOM=1 PARK_REVIEW_STRICT=1 node tests/ui-review.cjs
npm test
npm run test:desktop
```

[전 측정](../ui-review/loop3/before-measurements.json) · [후 측정](../ui-review/loop3/after-measurements.json). 출력은 /tmp/park-workdesk-review/loop3-after이며 실제 사용자 프로필을 읽지 않는다.

기관 Windows 실기기의 스크린리더, 고배율 글꼴, 날짜 입력 위젯과 실제 절전·토스트는 후속 확인 대상이다. 다음 기능 백로그는 반복 일정 회차별 완료/예외(TASK-CALENDAR-02)다. 이번 검토는 범위 내 종료 승인이고 전체 제품의 완성을 의미하지 않는다.
