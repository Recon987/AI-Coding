# 독립 에이전트 UI 검토 루프

사용자가 전반적인 화면 완성도를 지적하여 역할을 나눠 실제 화면으로 두 차례 검토했다. 새 기능 수를 평가 점수로 대체하지 않았다.

## 역할과 절차

- visual_review: 화면 위계·타이포·색상·밀도·일관성, 전후 캡처 독립 검토.
- workflow_review: 조회/작성/수정/검색 상태와 입력 유실·완료 범위 검토.
- implementation_review: CSS 누적·대비·반응형·접근성 검토. 이후 TASK-TRAY 설계 검토.
- editor_implementation / design_implementation: 파일 소유 범위를 분리해 편집 흐름과 시각 체계를 수정.
- ui_review_harness: 가상 자료·해상도를 고정한 Electron 캡처/geometry 도구 작성.
- root: 검토 취합, 원격 Gemini 달력 변경 통합, 회귀 검증·커밋·푸시. 구현 담당이 자신의 결과를 최종 승인하지 않았다.

첫 검토 → 구현 → Round 1 독립 검토 → P0 보정 → Round 2 독립 검토 → 실제 동작 검증 순서다. 이후에도 아래 명령과 같은 fixture로 재현할 수 있다.

```sh
npm run build
PARK_REVIEW_STAGE=after PARK_REVIEW_ZOOM=1 PARK_REVIEW_STRICT=1 node tests/ui-review.cjs
```

출력은 기본 `/tmp/park-workdesk-review/after/`이다. 1280×800, 1360×900, 960×680 및 1280×800 125% 확대, 빈 화면/일반 자료/긴 문자열/직원14명(미등록2명)을 검사한다. 자료는 임시 프로필에만 쓰며 실제 기록에 접근하지 않는다.

## 구현과 검증

- 조회는 전체 폭 요약 목록, 전문은 펼쳐 읽기. 추가/수정은 공통 편집 시트로 분리했다.
- 통합 검색은 원본 화면 위에 열어 초안을 보존한다. 미저장 표시·닫기 확인·저장 실패 시 내용/오류 유지, 포커스 복귀를 공통 처리한다.
- 근무표 집계를 얇게 줄이고 실제 집계와 필터를 일치시켰다. 좁은 표의 이름/수정 고정 열과 버튼 줄바꿈을 보정했다.
- Gemini TASK-CALENDAR-01 공휴일·반복 일정·종료일 UI와 데이터 계약을 보존했다. 반복 완료가 전체 회차에 적용됨을 UI에 명시했다.
- 최종 배치 검사 83개 통과, 페이지 오류0·외부 요청0. 데이터 테스트22개 및 실제 Electron 업무 흐름 통과. 검색 중 초안 유지, 취소 거부, IPC 저장 실패 시 입력 보존을 회귀 검증했다.
- 파일 대화상자 및 JavaScript 확인창의 UI만 테스트에서 대체하며 상태·저장 로직은 실제 앱을 실행한다. OS 네이티브 창의 시각적 완성도까지 자동 검증했다고 표현하지 않는다.

## 남은 개선

좁은 주간표는 표 안 가로 스크롤을 사용한다(안내 문구 추가). 긴 이름·거점의 전체값 읽기, 달력 셀의 유형/제목 비중, 첫 사용 화면, 날짜 표시와 타이포 세부 정리는 후속 검토한다. 반복 일정 400회 탐색 상한은 검토 당시 선행 수정 대상으로 기록했으며, TASK-TRAY-01에서 요청 구간으로 이동하도록 수정했다. 회차별 완료/예외일은 TASK-CALENDAR-02로 남긴다.
