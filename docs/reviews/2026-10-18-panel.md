- 근거: `1280x800-patrol-new.png`, `1280x800-notes-new.png`, `1280x800-calendar-new.png`, `960x680-patrol-new.png` — 제목 줄(68px) 아래에 저장·취소만 있는 줄(60px)이 하나 더 있다. `Sheet.tsx:76-84`의 "닫기 ×"와 각 편집기의 "취소"(`Patrols.tsx:273-279` 등)는 같은 동작이다. 반면 `form-export-patrol.png`(양식 출력)는 실행 버튼이 **하단**에 전체 폭으로 있어 시트마다 버튼 위치가 다르다. 메모(2칸)·일정(3칸)도 600px 고정 폭(`style.css:459`)이라 오른쪽 절반과 아래 2/3가 비어 있고, 순찰 편집창은 960x680에서 "확인 사항" 칸이 접히는 선 아래에 있다(1차 U5가 아직 남음).
- 개선안:
  1. `Sheet`에 `actions?: ReactNode` prop을 추가해 머리 한 줄에 `[제목 ……… 취소 | 저장]`을 둔다. Outlook 일정 창, macOS 시트처럼 저장이 맨 위 오른쪽에 있다. 텍스트 "닫기 ×"는 지우고 Esc와 `취소`로 닫는다(Esc 경로는 이미 `onCancel`에 있다). `.sheet .editor > .editor-header-actions`의 sticky 둘째 줄(`style.css:465`)을 삭제하면 머리 높이가 128px에서 68px로 준다.
  2. `Sheet`에 `size?: "sm" | "md"`를 추가한다. `.sheet.sm { width: 480px }`은 메모·전화메모·일정·통제·조직·거점에, `md`(600px)는 순찰·양식 출력에 쓴다.
  3. 양식 출력 시트(`FormExport.tsx`, `.sheet-actions`)도 같은 머리 버튼 배치로 맞춘다. 시트는 모두 "머리 오른쪽에 주 행동" 하나로 통일한다.
  4. 편집기 `form`에 `Ctrl+Enter = submit`을 추가한다. 저장 버튼 `title`에 단축키를 표시한다.
- 규모: M (Sheet/EditorDialog, 편집기 7곳, CSS 10줄, 스모크 테스트 선택자)
- 다른 역할과 충돌 가능성: 접근성/품질 역할 — `tests/desktop-smoke.cjs`가 "닫기" 버튼 이름이나 `.editor-header-actions`로 찾는다면 선택자를 갱신해야 한다. 닫기 아이콘을 남길 경우 `aria-label`은 유지한다. 안전 역할 — 변경 감지(`dirty`)·확인창 경로는 그대로 둔다.

## U2. 목록 행마다 수정·삭제가 항상 펼쳐져 있고, 화면마다 행 동작 위치가 다르다
- 심각도: 높음
- 근거: `1280x800-notes.png` — 한 줄짜리 메모 행이 동작 줄 때문에 약 105px이고 한 화면에 5건만 보인다. 상태 열은 전부 "메모" 태그다(`Personal.tsx:122`). 행 동작 배치는 화면마다 세 가지다. 아래 줄(`ListRow.tsx:56-69`, 순찰·메모·통제), 오른쪽 끝 버튼(`1280x800-office-directory.png`의 수정|삭제, `1280x800-office-day.png`의 수정), 그리고 홈의 → 화살표다. 삭제 색도 목록은 빨강, 직원 목록은 옅은 분홍이다. 순찰 목록 안에서도 v0.7.0 `960x680-patrol.png`의 "수정"은 초록 글자 링크인데 메모의 "수정"은 테두리 버튼이어서(ListRow는 첫 동작만 테두리) 같은 단어가 두 모양이다.
- 개선안:
  1. `ListRow`의 `.record-actions`를 summary 그리드의 마지막 열(`grid-template-areas`에 `actions`, `--row-cols` 끝에 `auto`)로 옮겨 행 오른쪽 끝에 붙인다. 직원 목록·근무현황과 같은 위치가 된다.
  2. 보조 동작(수정·삭제)은 `.list-row:hover, .list-row:focus-within, .record-details[open]`일 때만 `opacity:1`로 보이고, 평소에는 `opacity:0`으로 둔다. `visibility`는 쓰지 않아 Tab 이동이 유지된다. 상태를 바꾸는 동작(처리 완료, 오늘 해제, 인수인계로 연결)은 항상 보인다. Linear·Things의 행 동작 방식이다.
  3. 버튼 모양은 "상태 변경 = 테두리 small, 수정 = text-button, 삭제 = text-button danger" 한 규칙으로 정해 `ListRow`·`OfficeDirectory`·`Office`가 같은 클래스를 쓰게 한다. 직원 목록의 옅은 삭제색(별도 클래스)은 지운다.
  4. 업무 메모는 상태가 없으므로 `status` 대신 수정일을 넣거나 열을 없앤다(`ListHeader compact` 변형 추가).
  - 기대 효과: 메모·순찰 행 높이 약 105px → 약 64px, 1280x800 한 화면 5건 → 8~9건.
- 규모: M
- 다른 역할과 충돌 가능성: 접근성 역할 — hover 노출은 처음 쓰는 사람이 기능을 찾기 어렵다는 반론이 있을 수 있다. 절충안은 오른쪽 정렬 + 항상 표시 + `--muted` 색이다. 데스크톱 스모크 테스트가 행 버튼을 클릭한다면 hover 상태가 필요할 수 있다.

## U4. 달력: 날짜 칸이 나오기 전에 약 350px를 쓰고, 1200px 이하에서는 선택 날짜 목록이 화면 밖으로 밀린다

## S4. Windows에서 일시적인 파일 잠금 때 저장이 바로 실패함(재시도 없음)
- 심각도: 중간 (미재현: Linux 환경이라 확인 불가)
- 근거: `store.cjs:32` `fs.renameSync(temporary, file)`가 한 번만 시도한다. Windows에서는 백신(V3 등)·검색 색인·백업 도구·OneDrive/폴더 리디렉션이 대상 파일을 잠깐 열고 있으면 rename이 `EPERM`/`EBUSY`/`EACCES`로 실패하는 일이 흔하다(npm graceful-fs가 같은 이유로 재시도한다). 실패하면 원시 오류 문구("EPERM: operation not permitted, rename …")가 표시되고, 편집 창은 열린 채 남지만 목록에서 바로 처리하는 동작(완료 표시, 삭제 등)은 다시 해야 한다. 시작 시 읽기에서 같은 일시 오류가 나면 `recovery.cjs:16`이 손상 처리로 들어가 손상본 사본을 만들고 복구 대화상자를 띄운다.
- 개선안: rename·open에서 위 오류 코드일 때 짧게 대기하며 재시도(예: 최대 10회, 1초 이내)한다. 시작 읽기에서는 `ENOENT` 이외의 입출력 오류(`EBUSY`/`EPERM`)를 "손상"과 구분해 "잠시 후 다시 시도" 선택지를 준다. 실패 문구를 한국어로 바꾼다.
- 규모: S
- 다른 역할과 충돌 가능성: 없음. Windows Actions 결과와 기관 실기기 확인을 구분해 기록해야 한다.

## A1. 목록 행의 "수정·삭제" 버튼과 주간 근무표 셀의 접근 가능한 이름이 어긋남

## A2. 저장 중(`busy`) 버튼을 `disabled`로 바꿔 키보드 포커스가 문서 처음으로 사라짐
- 심각도: 높음 (2.4.3 포커스 순서, 2.1.1)
- 근거: 포커스가 있던 컨트롤이 저장 중에 `disabled`가 되면 Chromium은 포커스를 `body`로 보낸다. 저장이 끝나도 원래 자리로 돌아오지 않는다.
  - 행 동작 버튼 `ListRow.tsx:59`, 달력 완료 체크박스 `Calendar.tsx:216`, 회차 제외 `Calendar.tsx:243`, 통제 해제, 사무소 탭 `Office.tsx:175`, 왼쪽 메뉴 전체 `main.tsx:321`, 근무표 셀 `Office.tsx:456`.
  - 예를 들어 달력에서 체크박스로 "회차 완료"를 누르면 저장 뒤 Tab이 사이드바 첫 항목부터 다시 시작한다. 목록 중간에서 작업하던 키보드 사용자는 매번 수십 번 Tab을 다시 눌러야 한다.
  - 시트의 저장 버튼은 닫힐 때 `Sheet.tsx:46`이 포커스를 복구하므로 이 문제가 없다. 시트 밖의 즉시 동작만 해당한다.
- 개선안: 즉시 동작 컨트롤은 `disabled` 대신 `aria-disabled="true"`를 쓰고 클릭 핸들러에서 `busy`면 무시한다(포커스 유지). 아니면 공용 훅을 둔다: `save()` 전에 `document.activeElement`의 `id`/`data-focus-key`를 기억하고 `busy=false` 뒤에 같은 키의 요소로 `focus()`한다. 메뉴의 `disabled={busy}`(`main.tsx:321`)는 `navigate`에 이미 `saving.current` 가드(`main.tsx:201`)가 있으니 제거해도 된다.
- 규모: M
- 다른 역할과 충돌 가능성: 중간. 자료 무결성 역할은 중복 저장 방지를 요구한다. `aria-disabled`와 핸들러 가드로 중복 실행은 그대로 막히므로 기능상 충돌은 없다. 다만 시각 스타일(`button:disabled { opacity:.48 }`)을 `[aria-disabled=true]`에도 맞춰 줘야 한다.

## A3. 입력 오류가 해당 필드와 연결되지 않고 필수 표시가 레이블에 없음

- 근거:

  - `<form noValidate>`로 기본 말풍선을 끄고 같은 위치에 앱 자체 문구를 보여 주면 모든 시트가 같은 방식이 된다.
- 규모: M
- 다른 역할과 충돌 가능성: 중간. 디자인 역할이 "한 화면 한 주 버튼"이나 시트 머리의 고정 저장 영역을 유지하려 할 수 있다. 이 개선은 버튼 위치를 바꾸지 않는다. 자료 검증 규칙(저장 전 거부)은 그대로 둔다.

## 교차 검토 — 역할 1 현장 직원 관점 (2026-10-18)

읽기 전용. 다른 역할의 발견마다 현장 직원 입장에서 한 줄 의견을 적는다.

## 1. 다른 역할 발견에 대한 의견

### UX·디자인 (U)
- **U1 시트 머리 단일화 — 찬성.** 순찰 직후 짧게 입력할 때 저장이 한 줄 위에 있고 확인 사항 칸이 첫 화면에 보이는 것이 곧 입력 속도다. Ctrl+Enter 저장도 반긴다.
- **U2 행 동작 hover 노출 — 조건부.** 고령·비숙련 직원은 숨은 버튼을 찾지 못한다. 오른쪽 정렬과 버튼 모양 통일에는 찬성한다. 숨김 대신 "항상 표시 + muted 색" 절충을 요구한다.
- **U3 주 행동 위치 통일·띠/탭 중복 정리 — 조건부.** 통일에는 찬성한다. 당직자 이름은 아침 확인의 핵심이므로, 띠에서 이름을 숨긴다면 바로 아래 한 줄로 보여야 한다.
- **U4 달력 공간·2열 유지 — 찬성.** 통제·제출 마감을 한눈에 봐야 하는 화면이다. 이름 "일정"으로 바꾸는 것에도 이견이 없다.
- **U5 비정보 요소 정리 — 찬성(3번은 0건일 때 접기).** 순찰 화면 1순위는 기록이다. 단속이 있는 주에는 집계가 위에 보여도 된다.
- **U6 문구 통일 — 찬성.** 단어는 "추가"보다 "등록"이 공공기관 업무 말투에 가깝다고 본다 [확인 필요]. 저장 버튼은 "저장" 하나로 통일한다.
- **U7 로고·영문 부제·한국식 날짜 입력 — 찬성.** 특히 `10/15/2026 09:30 AM` 표기는 현장 기록 시각 오기를 부른다. 2번(lang ko-KR)을 우선한다.
- **U8 빈 상태 품질 — 찬성.** 영향은 작지만 S 규모라 비용이 낮다.

### 자료 안전·보안 (S)
- **S1 시간대 차이로 전체 파일 거부 — 찬성(최우선).** 새 PC 기본 시간대 문제는 기관 PC 교체 때 실제로 생길 수 있고, 생기면 모든 기록을 열 수 없다.
- **S2 버전 혼용 시 통제 기록 소실 — 조건부.** 현장 USB portable 사용이 현실적이므로 위험은 크다. 다만 스키마 필드 추가는 승인이 필요하다. 3번(메모 편집 시 필드 보존)만 먼저 하자.
- **S3 세대 보호본 — 조건부.** 잘못된 근무표 반입 복구에는 필요하다. 보존 개수와 평문 사본 증가 문제는 사용자 결정 사항이다.
- **S4 Windows 파일 잠금 재시도 — 찬성.** 기관 PC 백신(V3) 환경에서 "EPERM" 영문 오류가 나면 현장 직원은 대처할 수 없다.
- **S5 복원 대화상자에 시각·건수 표시 — 찬성.** "어느 백업이 어제 것인지"를 모르면 복원을 하지 않게 된다.
- **S6 두 번째 구버전 백업 — 찬성.** S 규모이고 원칙 준수 문제다. 현장 체감은 낮다.
- **S7 UNC 경로 확인·IPC 발신자 확인 — 조건부.** 공유 폴더 바로가기를 매일 쓴다면 매번 확인은 불편하다. "복원·반입한 자료에 한해 최초 1회 확인"이면 찬성한다.
- **S8 초안 자동 보관 — 찬성(후순위).** 긴 순찰 기록을 잃는 것은 치명적이다. 다만 새 IPC와 평문 파일이 생기므로 다음 주기에 한다.

### 접근성 (A)
- **A1 행 버튼 접근 가능한 이름 — 찬성.** 화면낭독기 사용자가 아니어도, 이름이 붙으면 잘못된 기록 삭제를 막는 확인 문구 개선으로 이어진다.
- **A2 busy 중 포커스 상실 — 찬성.** 키보드로 연속 처리(완료 체크)할 때의 불편이 실제로 크다.
- **A3 필드별 오류·필수 표시 — 찬성.** 필수 항목이 바뀌는 D2(제목 선택화)와 함께 하면 좋다. 좌표 오류로 저장이 막히는 이유를 보여 주는 것은 현장 입력에 직접 도움이 된다.
- **A4 고대비·입력칸 테두리 — 찬성.** 저시력·고령 직원과 밝은 사무실 모니터에서 입력칸이 안 보이는 문제가 있다.
- **A5 상태 메시지 유지·낭독 — 찬성.** 4.5초는 현장 복귀 직후 확인하기에 짧다.
- **A6 잘린 텍스트 — 조건부.** 당직 타일과 근무표 이름 잘림은 고쳐야 한다. 달력 칩 2줄화는 확대 상태에서만 적용하는 데 동의한다.
- **A7 월간 달력 로빙 tabindex — 찬성(후순위).** 현장 체감은 중간이다.
- **A8 "/" 단축키 끄기 — 찬성.** "/"를 빼고 Ctrl+K만 남기는 쪽을 선호한다. 담당구역 "3/2"처럼 사선을 쓰는 표기와도 헷갈리지 않는다.

### 코드 품질 (C)
- **C1 전역 검색과 화면 검색 불일치 — 찬성.** "담당구역 3-2"나 "흡연"으로 전역 검색이 안 되는 것은 현장 직원에게 명백한 결함이다.
- **C2 날짜 계산 통합 — 찬성.** 단, 브리핑을 수정하는 D1과 같은 파일을 건드리므로 순서를 정해야 한다.
- **C3 라벨 단일 정의 — 찬성.** D6 용어 교체의 선행 작업이다.
- **C4 category 문자열 분기 — 찬성.** 현장 영향은 없지만, 용어를 바꿀 때 오동작을 막아 준다.
- **C5 shared 타입 검사 — 찬성(후순위).** 현장 영향은 간접적이다.
- **C6 대형 컴포넌트 분리 — 조건부.** 이번 주기에 화면 개선과 함께 하면 충돌 위험이 있다. 별도 주기에 하자.
- **C7 스모크 보일러플레이트 — 찬성(후순위).** 현장 영향은 없다.
- **C8 계약 단위 테스트 — 찬성.** D1의 브리핑 문구 변경을 고정하는 데 필요하다.

## 2. 이번 세션 구현 추천 TOP 5 (S/M, 사용자 승인 불필요 범위)

1. **S1 시간대에 따른 전체 파일 거부 해소 (S)** — 발생하면 모든 업무 기록이 잠긴다. 읽기 검증에서 지역 시간대 의존을 없애고 TZ 3종 테스트로 고정한다.
2. **D2 순찰 입력 부담 축소 (M)** — 최근 기록에서 기록자·종류·구역을 기본값으로 가져온다. 제목은 비우면 자동으로 채운다(저장 계약은 유지). "이 기록으로 새 순찰"을 추가한다. 필수 표시는 A3의 Field `required` 표기와 같이 넣는다.
3. **D1 브리핑 텍스트에 당직·근무 현황과 전날 단속 요약 추가 (S~M)** — 파생만 하고 저장은 바꾸지 않는다. C8 방식으로 briefing 문구 테스트를 붙이고, 같은 김에 `briefing()` 날짜 검증을 `validDate`로 바꾼다(C2 일부).
4. **C1 검색 텍스트 단일화 (S)** — 담당구역·순찰 종류·단속 유형으로 전역 검색이 되게 한다. D4-①의 공백 정규화를 같은 shared 함수에 둘 수 있다.
5. **S4 Windows 파일 잠금 재시도와 한국어 오류 문구 (S)** — 기관 PC 백신 환경에서 저장 실패를 막는다.

차순위(시간이 남으면): D3 인계 본문 보강·담당자 datalist(S), A2 포커스 유지(M), U7-2 한국식 날짜·시각 입력(S, Windows 실기기 확인은 따로 기록), S2-3 메모 편집 시 필드 보존(S).

## 3. 정리가 필요한 상충

- **U2 hover 노출 ↔ A1·현장 발견성**: 숨기지 말고 "오른쪽 정렬 + 항상 표시 + muted 색"으로 정리하자. 처리 완료·오늘 해제·인수인계 연결은 강조색을 유지한다.
- **U3-3 당직 이름 숨김 ↔ D1 아침 확인**: 띠에는 인원 수, 바로 아래 줄에 이름 전체(2줄 허용, A6과 같은 방향)를 둔다.
- **U5-3 집계 접기 ↔ 단속 실적 확인**: 0건이면 한 줄로 접고, 1건 이상이면 펼친다. 위치는 목록 위로 유지한다.
- **U6 "추가" ↔ "등록"**: 한 단어로 통일하는 데는 동의한다. 기록류에는 "등록"을 제안하며 [확인 필요]로 사용자가 결정한다.
- **C2·C6 리팩터 ↔ D1·U4 화면 변경**: 같은 파일(Briefing·Calendar·model)을 고친다. 이번 세션에서는 D1을 먼저 하고 C2는 briefing의 validDate 한 줄만 한다. C6는 다음 주기로 미룬다.
- **C3 ↔ D6 용어 교체**: C3(라벨 한 곳 정의)을 먼저 한다. D6 라벨 문구는 사용자 확인 후 한 줄만 바꾼다.
- **S7 UNC 확인 ↔ 공유 폴더 일상 사용**: 확인은 복원·반입 자료에 한해 최초 1회로 한다.
- **S3·S8 평문 사본 증가 ↔ TASK-SECURITY-01**: 보존 개수와 암호화 순서는 사용자 결정 사항이므로 이번 세션에서 제외한다.

## 2차 교차 의견 — 역할 2 (UX·시각 디자인)

## 다른 역할 발견에 대한 의견

### 현장 직원(D)
- D1 브리핑에 당직·근무, 전날 단속 추가 — **찬성**: 화면 상단 띠에 있는 정보가 출력물에도 있어야 화면과 출력이 일치한다.
- D2 순찰 입력 기본값·제목 선택·폼 순서 변경 — **찬성**: 첫 칸이 중복 입력(제목)인 것은 시각적으로도 가장 큰 마찰이다. 순서 변경은 U1 시트 머리 정리와 같이 하면 필수 칸이 모두 첫 화면에 들어온다.
- D3 인계 본문 보강·담당자 datalist — **찬성**: 화면 변화가 거의 없고 datalist는 Windows 기본 컨트롤이라 일관성 문제가 없다.
- D4 단속 유형 공백 정규화·새 유형 안내 — **조건부**: 안내 문구는 필드 바로 아래 `--fs-xs` 한 줄(A3의 hint 자리)로만 넣는다. 경고색은 쓰지 않는다.
- D5 통제 시각·지난 통제 복사 — **조건부**: ② 복사는 찬성한다. ① 시각 필드는 달력 칩 표기 규칙(시각 접두)을 정한 뒤 진행한다.
- D6 확인 등급 라벨·"이상 없음" 버튼 — **찬성**: "일반 기록" 같은 어색한 값이 사라진다. 버튼은 확인 사항 칸 바로 아래 보조(테두리) 버튼으로 둔다.
- D7 근무 구분 확장 — **조건부**: datalist 단계는 찬성한다. enum 확장은 근무 칩 색 토큰(`--work-*`)이 늘어나므로 색 체계를 먼저 정해야 한다.
- D8 양식 출력 기록자·구역 필터 — **찬성**: 양식 출력 시트에 select 1개만 추가되어 화면 부담이 작다.

### 자료 안전·보안(S)
- S1 시간대 의존 읽기 검증 제거 — **찬성**: 전체 잠김은 어떤 화면 개선보다 사용자 경험 피해가 크다.
- S2 `minReader`·읽기 전용 열기 — **조건부**: 읽기 전용 상태를 상단바 저장 표시 자리에 고정 배지로 보여 주는 화면 설계가 같이 있어야 한다. 스키마 변경이므로 이번 세션 범위 밖이다.
- S3 일 단위 세대 보호본 — **찬성**: 화면 영향은 "자료 관리" 메뉴의 복원 목록뿐이다.
- S4 파일 잠금 재시도·한국어 오류 — **찬성**: 영문 오류 노출은 미완성 인상의 큰 원인이다.
- S5 복원 대화상자에 시각·건수 표시 — **찬성**: 확인창에 건수 표를 넣는 것은 Outlook·Windows 백업 복원 화면과 같은 관례다.
- S6 구버전 원본 백업 이름 충돌 — **찬성**: UI 영향 없음.
- S7 UNC 경로 확인·IPC 발신자 확인 — **찬성**: 확인창 문구만 기존 앱 확인 UI(confirm.ts)와 같은 모양으로 맞춘다.
- S8 초안 자동 보관·복구 제안 — **조건부**: 시작 시 복구 제안은 모달 대신 홈 상단 한 줄 notice로 한다. 규모 M이고 저장소 설계가 필요해 다음 주기로 미룬다.

### 접근성(A)
- A1 행 동작·근무표 셀 접근 이름 — **찬성**: 시각 변화가 없다. U2 개편 때 `ListRow`가 `${title} ${label}`을 자동으로 만들게 한다.
- A2 `busy` 중 `disabled` 대신 `aria-disabled` — **찬성**: `[aria-disabled=true]`에 `button:disabled`와 같은 시각 스타일을 주는 조건이다.
- A3 필드별 오류·필수 표시 — **찬성**: 상단 한 줄 오류보다 필드 아래 오류가 UX 관례(Fluent·KRDS)에도 맞다. "(필수)" 글자는 `--muted` 작은 글씨로 둔다.
- A4 입력칸 대비·강제 색상 모드 — **조건부 찬성**: 입력·선택·체크박스 테두리에만 적용하고 카드·구분선·버튼 테두리는 지금대로 둔다.
- A5 상주 라이브 영역·알림 유지 시간 — **찬성**: 시각 알림에 닫기 버튼을 두는 것도 좋다. 8~10초 유지에 동의한다.
- A6 잘린 텍스트 줄바꿈·포커스 툴팁 — **조건부**: 달력 칩·당직 타일·근무표 셀에만, 좁은 폭(≤1200px 또는 컨테이너 쿼리)에서만 2줄을 허용한다. 목록 행 제목은 1줄을 유지한다(펼치면 전문이 보인다).
- A7 월간 달력 로빙 tabindex — **찬성**: 시각 변화가 없다. U4의 "선택 날짜 기록 N건 보기" 버튼 제거와 순서를 맞춰야 한다(A7은 이 버튼을 재사용하려 함). 넓은 화면에서도 두 열을 유지하면 버튼은 필요 없다.
- A8 "/" 단축키 끄기 — **찬성**: Ctrl+K만 남기는 안이 더 단순하다.

### 코드 품질(C)
- C1 검색 텍스트 단일화 — **찬성**: 사용자에게 "같은 검색인데 결과가 다름"은 신뢰를 깨는 UX 결함이다.

- **A6 줄바꿈 vs 밀도** — **조건부 찬성.**

- **D2 순찰 폼 재배치 vs U1 시트 머리** — **충돌 없음, 함께 구현을 권장한다.**

### U (UX·시각 디자인)
- **U1 시트 머리 한 줄 + "닫기 ×" 제거 + Ctrl+Enter — 조건부**
  - 조건 1: 닫기 버튼은 아이콘이라도 남기거나, 머리에 둔 "취소"를 Tab 순서상 첫 동작으로 둔다. Esc만으로는 마우스 사용자와 일부 고령 사용자에게 닫는 경로가 보이지 않는다.
  - 조건 2: Ctrl+Enter는 textarea 안에서도 동작해야 하고, `aria-keyshortcuts="Control+Enter"`와 화면에 보이는 힌트를 함께 둔다(`title`만으로는 부족하다).
  - 조건 3: 저장 버튼을 sticky 머리에 두면 125%·680px 화면에서 머리가 2줄로 늘어 본문을 가리지 않는지 확인한다.
  - 조건 4: 시트를 연 직후의 첫 포커스는 여전히 첫 입력 필드여야 한다.
- **U2 hover 시에만 보이는 행 동작 — 조건부(원안에는 반대)**

- **U3 주 행동 위치 통일·요약 띠를 필터로 — 조건부**

  - 띠를 필터 버튼으로 쓰려면 `aria-pressed`(또는 `aria-controls`)를 붙이고, 누른 뒤 결과 건수를 `role="status"`로 알려야 한다.
  - 당직 이름을 `display:none` + `title` 툴팁으로 숨기는 안에는 반대한다(A6). 이름은 두 번째 줄로 보내고 줄바꿈을 허용한다.
- **U4 달력 레이아웃 재구성 — 조건부**

  - 범례를 `details`로 접는 것은 괜찮다. 칩에 아이콘과 글자가 있어 색에만 의존하지 않는다.
