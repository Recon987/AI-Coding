- 근거: `1280x800-patrol-new.png`, `1280x800-notes-new.png`, `1280x800-calendar-new.png`, `960x680-patrol-new.png` — 제목 줄(68px) 아래에 저장·취소만 있는 줄(60px)이 하나 더 있다. `Sheet.tsx:76-84`의 "닫기 ×"와 각 편집기의 "취소"(`Patrols.tsx:273-279` 등)는 같은 동작이다. 반면 `form-export-patrol.png`(양식 출력)는 실행 버튼이 **하단**에 전체 폭으로 있어 시트마다 버튼 위치가 다르다. 메모(2칸)·일정(3칸)도 600px 고정 폭(`style.css:459`)이라 오른쪽 절반과 아래 2/3가 비어 있고, 순찰 편집창은 960x680에서 "확인 사항" 칸이 접히는 선 아래에 있다(1차 U5가 아직 남음).
- 개선안:
  1. `Sheet`에 `actions?: ReactNode` prop을 추가해 머리 한 줄에 `[제목 ……… 취소 | 저장]`을 둔다. Outlook 일정 창, macOS 시트처럼 저장이 맨 위 오른쪽에 있다. 텍스트 "닫기 ×"는 지우고 Esc와 `취소`로 닫는다(Esc 경로는 이미 `onCancel`에 있다). `.sheet .editor > .editor-header-actions`의 sticky 둘째 줄(`style.css:465`)을 삭제하면 머리 높이가 128px에서 68px로 준다.
  2. `Sheet`에 `size?: "sm" | "md"`를 추가한다. `.sheet.sm { width: 480px }`은 메모·전화메모·일정·통제·조직·거점에, `md`(600px)는 순찰·양식 출력에 쓴다.
  3. 양식 출력 시트(`FormExport.tsx`, `.sheet-actions`)도 같은 머리 버튼 배치로 맞춘다. 시트는 모두 "머리 오른쪽에 주 행동" 하나로 통일한다.
  4. 편집기 `form`에 `Ctrl+Enter = submit`을 추가한다. 저장 버튼 `title`에 단축키를 표시한다.
- 규모: M (Sheet/EditorDialog, 편집기 7곳, CSS 10줄, 스모크 테스트 선택자)
- 다른 역할과 충돌 가능성: 접근성/품질 역할 — `tests/desktop-smoke.cjs`가 "닫기" 버튼 이름이나 `.editor-header-actions`로 찾는다면 선택자를 갱신해야 한다. 닫기 아이콘을 남길 경우 `aria-label`은 유지한다. 안전 역할 — 변경 감지(`dirty`)·확인창 경로는 그대로 둔다.

## U2. 목록 행마다 수정·삭제가 항상 펼쳐져 있고, 화면마다 행 동작 위치가 다르다
- 심각도: 높음
- 근거: `1280x800-notes.png` — 한 줄짜리 메모 행이 동작 줄 때문에 약 105px이고 한 화면에 5건만 보인다. 상태 열은 전부 "메모" 태그다(`Personal.tsx:122`). 행 동작 배치는 화면마다 세 가지다. 아래 줄(`ListRow.tsx:56-69`, 순찰·메모·통제), 오른쪽 끝 버튼(`1280x800-office-directory.png`의 수정|삭제, `1280x800-office-day.png`의 수정), 그리고 홈의 → 화살표다. 삭제 색도 목록은 빨강, 직원 목록은 옅은 분홍이다. 순찰 목록 안에서도 v0.7.0 `960x680-patrol.png`의 "수정"은 초록 글자 링크인데 메모의 "수정"은 테두리 버튼이어서(ListRow는 첫 동작만 테두리) 같은 단어가 두 모양이다.
- 개선안:
  1. `ListRow`의 `.record-actions`를 summary 그리드의 마지막 열(`grid-template-areas`에 `actions`, `--row-cols` 끝에 `auto`)로 옮겨 행 오른쪽 끝에 붙인다. 직원 목록·근무현황과 같은 위치가 된다.
  2. 보조 동작(수정·삭제)은 `.list-row:hover, .list-row:focus-within, .record-details[open]`일 때만 `opacity:1`로 보이고, 평소에는 `opacity:0`으로 둔다. `visibility`는 쓰지 않아 Tab 이동이 유지된다. 상태를 바꾸는 동작(처리 완료, 오늘 해제, 인수인계로 연결)은 항상 보인다. Linear·Things의 행 동작 방식이다.
  3. 버튼 모양은 "상태 변경 = 테두리 small, 수정 = text-button, 삭제 = text-button danger" 한 규칙으로 정해 `ListRow`·`OfficeDirectory`·`Office`가 같은 클래스를 쓰게 한다. 직원 목록의 옅은 삭제색(별도 클래스)은 지운다.
  4. 업무 메모는 상태가 없으므로 `status` 대신 수정일을 넣거나 열을 없앤다(`ListHeader compact` 변형 추가).
  - 기대 효과: 메모·순찰 행 높이 약 105px → 약 64px, 1280x800 한 화면 5건 → 8~9건.
- 규모: M
- 다른 역할과 충돌 가능성: 접근성 역할 — hover 노출은 처음 쓰는 사람이 기능을 찾기 어렵다는 반론이 있을 수 있다. 절충안은 오른쪽 정렬 + 항상 표시 + `--muted` 색이다. 데스크톱 스모크 테스트가 행 버튼을 클릭한다면 hover 상태가 필요할 수 있다.

## U4. 달력: 날짜 칸이 나오기 전에 약 350px를 쓰고, 1200px 이하에서는 선택 날짜 목록이 화면 밖으로 밀린다

## S4. Windows에서 일시적인 파일 잠금 때 저장이 바로 실패함(재시도 없음)
- 심각도: 중간 (미재현: Linux 환경이라 확인 불가)
- 근거: `store.cjs:32` `fs.renameSync(temporary, file)`가 한 번만 시도한다. Windows에서는 백신(V3 등)·검색 색인·백업 도구·OneDrive/폴더 리디렉션이 대상 파일을 잠깐 열고 있으면 rename이 `EPERM`/`EBUSY`/`EACCES`로 실패하는 일이 흔하다(npm graceful-fs가 같은 이유로 재시도한다). 실패하면 원시 오류 문구("EPERM: operation not permitted, rename …")가 표시되고, 편집 창은 열린 채 남지만 목록에서 바로 처리하는 동작(완료 표시, 삭제 등)은 다시 해야 한다. 시작 시 읽기에서 같은 일시 오류가 나면 `recovery.cjs:16`이 손상 처리로 들어가 손상본 사본을 만들고 복구 대화상자를 띄운다.
- 개선안: rename·open에서 위 오류 코드일 때 짧게 대기하며 재시도(예: 최대 10회, 1초 이내)한다. 시작 읽기에서는 `ENOENT` 이외의 입출력 오류(`EBUSY`/`EPERM`)를 "손상"과 구분해 "잠시 후 다시 시도" 선택지를 준다. 실패 문구를 한국어로 바꾼다.
- 규모: S
- 다른 역할과 충돌 가능성: 없음. Windows Actions 결과와 기관 실기기 확인을 구분해 기록해야 한다.

## A1. 목록 행의 "수정·삭제" 버튼과 주간 근무표 셀의 접근 가능한 이름이 어긋남

## A2. 저장 중(`busy`) 버튼을 `disabled`로 바꿔 키보드 포커스가 문서 처음으로 사라짐
- 심각도: 높음 (2.4.3 포커스 순서, 2.1.1)
- 근거: 포커스가 있던 컨트롤이 저장 중에 `disabled`가 되면 Chromium은 포커스를 `body`로 보낸다. 저장이 끝나도 원래 자리로 돌아오지 않는다.
  - 행 동작 버튼 `ListRow.tsx:59`, 달력 완료 체크박스 `Calendar.tsx:216`, 회차 제외 `Calendar.tsx:243`, 통제 해제, 사무소 탭 `Office.tsx:175`, 왼쪽 메뉴 전체 `main.tsx:321`, 근무표 셀 `Office.tsx:456`.
  - 예를 들어 달력에서 체크박스로 "회차 완료"를 누르면 저장 뒤 Tab이 사이드바 첫 항목부터 다시 시작한다. 목록 중간에서 작업하던 키보드 사용자는 매번 수십 번 Tab을 다시 눌러야 한다.
  - 시트의 저장 버튼은 닫힐 때 `Sheet.tsx:46`이 포커스를 복구하므로 이 문제가 없다. 시트 밖의 즉시 동작만 해당한다.
- 개선안: 즉시 동작 컨트롤은 `disabled` 대신 `aria-disabled="true"`를 쓰고 클릭 핸들러에서 `busy`면 무시한다(포커스 유지). 아니면 공용 훅을 둔다: `save()` 전에 `document.activeElement`의 `id`/`data-focus-key`를 기억하고 `busy=false` 뒤에 같은 키의 요소로 `focus()`한다. 메뉴의 `disabled={busy}`(`main.tsx:321`)는 `navigate`에 이미 `saving.current` 가드(`main.tsx:201`)가 있으니 제거해도 된다.
- 규모: M
- 다른 역할과 충돌 가능성: 중간. 자료 무결성 역할은 중복 저장 방지를 요구한다. `aria-disabled`와 핸들러 가드로 중복 실행은 그대로 막히므로 기능상 충돌은 없다. 다만 시각 스타일(`button:disabled { opacity:.48 }`)을 `[aria-disabled=true]`에도 맞춰 줘야 한다.

## A3. 입력 오류가 해당 필드와 연결되지 않고 필수 표시가 레이블에 없음

- 근거:

  - `<form noValidate>`로 기본 말풍선을 끄고 같은 위치에 앱 자체 문구를 보여 주면 모든 시트가 같은 방식이 된다.
- 규모: M
- 다른 역할과 충돌 가능성: 중간. 디자인 역할이 "한 화면 한 주 버튼"이나 시트 머리의 고정 저장 영역을 유지하려 할 수 있다. 이 개선은 버튼 위치를 바꾸지 않는다. 자료 검증 규칙(저장 전 거부)은 그대로 둔다.
