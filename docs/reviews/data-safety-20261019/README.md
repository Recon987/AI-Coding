## DS-01: 조건·결과·원인

조건은 정상 백업 선택·확인·주파일 교체가 끝난 **뒤**, 오래된 보호본을 정리하기 위한 `fs.readdirSync`가 `EACCES`로 실패하는 경우다. 실제 파일 접근 오류의 발생 확률은 측정하지 않았다. 오류 주입은 임시 Electron 본체 프로세스에만 적용하고 복원 후 해제했다. IPC 처리기와 renderer 코드는 교체하지 않았다.

| 시점 | 실제 주파일 | 화면의 기록 | 마지막 정상본 |
| --- | --- | --- | --- |
| 시작 | 가상 복원 전 메모 | 가상 복원 전 메모 | 가상 복원 전 메모 |
| 백업 복원 직후 정리 오류 | 가상 백업에서 복원한 메모 | **가상 복원 전 메모**와 오류 안내 | 가상 백업에서 복원한 메모 |
| 오류 뒤 메모 정상 등록 | **복원 전 메모 + 추가 메모** | 복원 전 메모 + 추가 메모 | **복원 전 메모 + 추가 메모** |

복원된 기록이 주파일과 마지막 정상본에서 사라졌다. 선택했던 원본 백업 JSON은 그대로 남는다(`backupUnchanged: true`). 원본 백업까지 지워졌거나 영구 복구가 불가능하다는 의미는 아니다. 이 오류는 현재 업무 자료의 의도하지 않은 되돌림이므로 P1로 분류한다.

[화면 캡처](after-commit-listing.png)에서 오류 아래에 복원 전 메모가 그대로 보인다. [실제 결과 JSON](desktop-results.json)에 복원 직후/다음 저장 뒤 주파일·보호본의 제목 목록이 있다.

원인 연결:
1. `desktop/store.cjs:130`의 `restoreCopies(file)`는 디렉터리 열거 오류를 그대로 던진다. 개별 파일 삭제 오류만 내부에서 처리한다.
2. `desktop/main.cjs:146`에서 복원 주파일은 이미 확정됐지만148행의 정리 예외 때문에156행의 `return data`에 도달하지 못한다.
3. `src/main.tsx:255`의 restore IPC가 reject되어257행의 `setData`를 건너뛰고 오류만 표시한다. 다음 정상 저장이 이전 메모 상태를 디스크로 쓴다.

## Claude에게 넘기는 보완 조건

- 복원 **확정 이후** 정리 단계의 목록 읽기·삭제 실패는 경고로 전달하고, 확정한 복원 자료를 renderer로 반환한다.
- renderer에 복원 전 상태가 남아 다음 저장이 복원 자료를 덮는 경로를 막는다.
- 복원 **확정 이전** 백업 검증·보호본 작성·주파일 교체 실패는 계속 실패로 처리하고 이전 주파일을 보존한다.
- 정리에 실패한 보호본은 남기고 경고한다. 임의 삭제나 복원 자료 롤백을 추가하지 않는다.
- 아래 독립 실제 앱 감사가5/5 통과하고, 기존116개·desktop12개와 Windows 소스/패키지 검사가 유지되는지 확인한다. 정리 실패 회귀를 기존 CI에 편입하는 것은 구현자가 자신의 작업 범위에서 결정한다.

공용 소스와 Claude 카드 수정은 이번 감사에서 하지 않았다. 최소 구현 후보는 `desktop/main.cjs`에서 확정 뒤 정리 호출의 예외까지 경고로 처리하는 것이다. 실제 구현과 최종 승인은 총괄/구현자에게 남겼다.

신규 감사는 기존 npm test·스모크·CI 목록에 추가하지 않았다. 이름도 `*.test.cjs`와 달라 기존 단위 실행에 들어가지 않는다. 다음 명령으로 별도로 실행한다.

```sh
npm run build
node --test tests/data-safety-audit.cjs
node tests/desktop-data-safety-audit.cjs
```

마지막 명령은 기준20cdc3c에서 DS-01 때문에 **종료 코드1**을 반환한다. 통과로 바꾸려고 실패 검사를 생략하거나 기대값을 완화하지 않았다. 결과는 기본적으로 시스템 임시 폴더의 `park-data-safety-audit`에 쓴다. `PARK_DATA_AUDIT_DIR`로 출력 위치를 지정할 수 있다. 새 감사는 해당 기준의 코드·라벨 모듈을 사용하므로 수정 후 다시 실행할 때 새 체크아웃 해시를 결과와 함께 기록한다.

추가 실제 앱 검사의 첫 초안은 이전 버튼 이름 '메모 추가'를 찾다가 중단됐다. 새 라벨 모듈의 `addLabel("메모")`를 사용해 바로잡았고 최종 재실행은 UI 정상 저장까지 도달해 **실제 자료 덮어쓰기 단언**에서 실패했다. 초기 검사 작성 오류를 제품 결함으로 집계하지 않았다.

오류 주입은 디스크 고갈·권한 실패·짧은 부분 쓰기를 결정적으로 모사한 것이다. 실제 정전·백신 제품·Windows 권한 변경·기관 실기기를 시험한 것은 아니다. 최종 실제 앱 감사에서 처리되지 않은 renderer 오류0·외부 요청0을 확인했지만 의도한 복원 오류 안내는 화면에 존재한다.
