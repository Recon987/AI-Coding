# B1 구현 자체 검증 — 2026-10-20

## 판정과 책임

사용자가 승인한 B1(기록을 바로 작업으로 연결) 구현이다. **Codex 구현·자체 검증이며 Claude의 독립 승인 전이다.** Gemini가 확정한 메뉴·기한·1:N 기준을 반영했다. 제품 기준은 main `ea3105e`, 통합안 `b36307a`다. 보안 브랜치 `270cf7a`를 제품에 병합하지 않았다. 최초 원격 푸시는 자동 승인 검토에서 새 B1 게시 승인 부족으로 거절됐다. 이후 사용자가 게시를 명시 승인해 구현·검증 커밋 `77de23d`를 origin에 푸시하고 원격 SHA 일치를 확인했다. 이전 미게시 표시는 당시 기록이다.

## 사용자가 할 수 있는 일

- 오늘 화면에서 제목 한 줄로 사업·기한 없는 작업을 등록하고 완료한다. 입력 중 이동·종료에는 기존 미저장 보호를 적용한다.
- 인수인계·기한 도구에 `작업` 화면을 추가했다. 기존 인수인계·제출 화면에서도 `업무 유형 → 전체 유형`으로 세 유형을 함께 보고 관리한다. 기존 화면 기본 필터는 해당 유형을 유지한다.
- 상태는 할 일·진행 중·대기·완료. 완료 후 `다시 진행`, 인수인계는 `조치 완료`, 제출은 `제출 완료`다. 기존 전화의 처리 상태와 독립적이다.
- 메모·전화·최소 회의 기록 하나에서 후속 작업을 여러 개 만든다. 제목·내용을 채운 초안을 열고 기한 기본값은 없음이다. 원본 행의 완료 M/전체 N, 상세의 후속 이동·추가, 작업에서 원본 복귀를 지원한다.
- 출처를 삭제해도 작업 본문·연결은 보존한다. `출처: 삭제된 메모/전화메모/회의 기록`을 표시하고 복귀 링크를 만들지 않는다. 기존 순찰의 `patrolId` 연결·미완료 작업 재열기는 유지한다.
- 오늘 통합 목록은 경과→오늘→예정→무기한이며, 무기한은 우선순위·등록 순이다. 검색·달력·브리핑은 작업 원본에서 파생한다. 긴 작업 목록은 100건씩 표시한다.

## 10,000건 측정 조건

가상 작업 3,400·메모 2,000·전화 1,000·회의 500·기존 업무 500·순찰 100·연결 2,500으로 **총 10,000건**이다. 본문을 포함한 평문 저장 파일은 약 5.20MB(5,198,138바이트)다. 작업 10,000건에 다른 자료를 더한 조건과 구별한다.

Node 24.19.0, Linux x64, AMD EPYC 9V74, CPU 5개가 보이는 컨테이너에서 측정한다. 모델/읽기/저장은 3회 예열 뒤 30회, 실제 검색은 12회, 새 Electron 프로세스 시작·화면 저장은 3회다. 시작 측정은 파일 캐시가 따뜻한 조건이며 디스크 콜드 시작이 아니다. OS 파일 보호본을 포함한 저장 시간을 구분한다. 적은 표본의 p95는 최댓값에 가깝다. Windows 기관 PC의 성능 보장이 아니다.

## 검증 중 보정과 남은 일

첫 실행에 작업 빠른 등록이 추가돼 버튼 수 기대값을 4→5로 바꿨고, 새 `+ 후속 작업`을 기존 완료 동작과 구분되는 보조 버튼으로 검사하도록 확장했다. 복원 감사에서 빈 자료 생성과 정규화의 키 순서가 달라 문자열 비교가 실패했다. 빈 컬렉션 순서를 정규화와 일치시키고 안정성 검사를 추가했다. 보호본 실제 내용·원자적 저장 로직은 변경하지 않았다.

Claude는 이 브랜치에서 원본 상태 독립·1:N/삭제·기한 경계·기존 순찰 계약을 독립 검증하고, 보안 카드 통합 때 모델 충돌을 점검한다. Gemini는 구현 화면에서 명칭·혼합 목록·다중 후속 표기를 확인한다. Windows CI와 기관 실기기는 별도다. B2 사업/자료·B3 보고·실제 API·메신저·main 병합은 이 작업에 포함하지 않는다.
