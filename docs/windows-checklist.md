# Windows 실기기 확인

자동 검증과 실제 기관 PC 확인을 구분한다. 이 목록은 통과 결과가 아니라 확인 절차다.

1. GitHub Windows 빌드에서 npm 잠금 설치·단위 테스트·실제 Electron 테스트·NSIS/portable 생성을 확인한다. 결과는 해당 Actions 실행 로그로 판정한다.
2. Windows 10/11 x64 테스트 PC에서 설치 경로 선택·실행·종료·재실행·제거 확인. portable EXE도 데이터 경로가 유지되는지 확인한다. 코드 서명은 미설정이며 배포 승인 절차를 별도로 마련한다.
3. 외부 인터넷을 끊고 메모, 전화, 순찰, 인계, 제출 업무, 달력과 검색을 사용한다. 순찰→인계 연결, 완료/미완료 전환, 순찰 삭제 시 인계 내용 유지, 일정 원본 수정 반영을 확인한다.
4. 가까운 시각의 일정 및 제출 업무를 등록해 Windows 알림을 확인한다. 집중 지원·알림 허용 설정을 점검한다. 종료/절전 중 알림은 현재 지원하지 않는다.
5. v0.1 원본을 복사한 시험 프로필에서 v2 전환 후 원본 백업과 메모 보존을 확인한다. 전체 백업의 취소·복원·잘못된 파일 거부·복원 전 자동 보관을 확인한다.
6. 브리핑 TXT에 선택 날짜의 기록과 기준일까지 마감한 현재 미완료 업무가 들어가는지 확인한다. 기관 양식의 공식 보고서가 아닌 개인 정리 자료다.
7. 100%/125%/150%/200% DPI, 960px 이상 창과 다중 모니터에서 입력·스크롤·날짜 선택·한글 파일 경로를 확인한다.
8. 실제 자료 반입 전 저장 암호화·기관 개인정보·배포 정책을 검토한다. 기본 검증은 가상 자료만 사용한다.
