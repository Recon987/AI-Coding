# 공원 업무 수첩의 구조

## 현재 구현

Electron의 제한된 preload API로 로컬 파일 저장·폴더 열기·백업·브리핑 출력을 제공한다. renderer는 Node.js 직접 접근 없이 sandbox/contextIsolation에서 실행하고 외부 탐색과 새 창을 차단한다. 앱은 자동 업데이트나 외부 API를 호출하지 않는다.

`src/components/`는 업무별 화면, `shared/model.mjs`는 브라우저와 Electron이 공유하는 검증·달력·브리핑·알림 계산이다. `desktop/store.cjs`가 JSON의 원자 교체(임시 파일 fsync 후 이름 바꾸기)와 v1 원본 보존을 담당한다. 주 파일을 저장할 때마다 같은 내용의 `workdesk.json.last-good`도 원자적으로 갱신한다. `desktop/recovery.cjs`는 시작 시 자료를 읽지 못하면 손상 파일을 `.corrupt-<시각>.json`으로 먼저 보관(삭제하지 않음)한 뒤 마지막 정상본 사용·백업 복원·종료를 묻는다. 보관에 실패하면 아무것도 쓰지 않고 종료한다. 주 프로세스의 단일 인스턴스 잠금으로 동시에 여러 앱이 파일을 쓰는 것을 방지한다. 다중 사용자 또는 서버 DB용 구조는 아니다.

## 데이터 v3

v1의 notes/events/calls/folders 및 v2의 patrols/tasks를 보존하고 v3에 organizations/employees/bases/assignments를 추가했다. 조직 계층과 직원/거점 소속, 직원+날짜별 근무/당직을 UUID로 연결한다. shared/office.mjs가 참조·중복·날짜·거점·순환을 검증하고 현황을 계산한다. shared/office-import.mjs가 표준 CSV 반입을 전체 검증·미리보기한다. 순찰에는 시각·구간·기록자·확인 사항·현장 조치·확인 등급을 저장하고, 선택 필드로 순찰 종류(`kind`)·담당구역 번호(`zone`)·단속·확인 건(`observations[]`: 유형·건수·조치·메모·선택 위경도, 기록당 50개)을 둔다. 쓰지 않은 선택 필드는 저장하지 않아 기존 기록 모양을 유지한다. `patrolSummary`가 현지 날짜 기간으로 유형·조치별 건수를 합산한다. 업무에는 handover/submission 구분, 담당자·제출처·마감·알림 시점·완료 시각을 저장한다.

순찰과 후속 업무는 UUID로 연결한다. 미완료 연결 업무가 있으면 다시 연다. 순찰 삭제 시 인계 본문을 남기고 연결만 해제한다. 원본이 수정되어도 인계 시점의 본문 요약은 자동 덮지 않는다. 이후의 실시간 원문은 연결된 순찰에서 확인한다.

달력 항목은 순찰/업무/개인 일정에서 매번 계산한다. 업무를 일정으로 복제하지 않으므로 수정·완료·삭제가 바로 반영된다. 모든 원본은 전체 백업 대상이며 복원 전에 자료 버전, 형식, 순찰 참조, 완료 상태, 알림 범위를 검증한다. 20MB 및 종류별 10,000건 제한이 있다.

v1/v2 파일은 최초 시작 시 원본 바이트를 `.v1-backup.json` 또는 `.v2-backup.json`으로 보관한 뒤 v3로 전환한다. 브라우저도 버전별 원문을 별도 localStorage 키에 보관한다. 이전 앱은 v3를 읽지 못하므로 새 근무 자료를 손실시키지 않는다. 사무소 근무표는 개인 달력에 전 직원을 복제하지 않고 별도 현황판에서 원본을 참조한다. 실제 ERP 매핑은 docs/erp-integration.md 참조.

## 알림과 브리핑

개인 일정은 해당 시각, 업무는 마감 또는 1시간/1일 전에 알림 대상으로 계산한다. 실행 중 15초마다 최근 1분을 확인하고 초기 실행도 같은 범위다. powerMonitor resume에서는 지난24시간을 보충한다. 완료·미래 대상은 제외하고 4건 이상은 한개 요약 알림으로 묶는다. 회차ID와 알림시각의 조합으로 중복을 막으며 notification-receipts.json에24시간/최대50000건을 보관한다. OS 표시 요청 기준이며 실패 이벤트면 이력을 제거한다. OS 수신 보장은 아니다. 지난 업무는 브리핑에 계속 표시한다.

브리핑의 날짜별 일정·순찰은 해당 날짜 기준이다. 미완료 인계·제출은 선택 날짜까지 마감한 현재 미완료 기록, 전화는 현재 미처리 기록이다. 과거 시점의 상태를 재현하는 감사 보고서는 아니다. TXT는 로컬 자료에서 만들어 사용자가 선택한 파일에 저장한다.

## 후속 확장

민감자료를 다루기 전에 저장 암호화/키 복구/접근 통제를 구현한다. 기관 운영을 위한 데이터양·동시성은 SQLite와 API 서버 등으로 별도 확장한다. 네트워크 공유 폴더의 JSON/SQLite를 여러 PC에서 직접 여는 방식은 지원하지 않는다.

법령은 인터넷 구간 공식 수집 API → 출처·공포일·시행일·해시·서명을 포함한 반입 패키지 → 기관 검사/승인 → 폐쇄망 임시 적재/버전 전환으로 구성한다. 마지막 수집·반입 시각을 표시하고 현행/시행 예정 조문을 구분한다. 검색어를 외부 법령 사이트로 보내는 기능은 구현하지 않는다.

ERP는 승인된 읽기 전용 API나 뷰를 중계 서버에서 조회한다. 클라이언트에 ERP DB 계정을 배포하지 않는다. 개인 경조사·용돈 기록은 기관 업무 저장소 및 공유 대상과 별도 설계한다. 좌표 변환은 EPSG·축 순서·단위·기준점 검증, 파일명 변경은 미리보기·충돌 검사·되돌리기를 먼저 구현한다.

## PC 설정과 트레이 (TASK-TRAY-01)

`desktop/settings.cjs`는 업무 자료와 별도인 desktop-settings.json `{version:1,closeToTray:false}`를 엄격 검증·원자 저장한다. 손상 파일은 읽을 때 보존하고 기본값으로 시작하며 명시적인 재설정 때 보호본을 만든다. 설정과 알림 이력은 업무 백업/복원으로 덮지 않는다. preload에는 `getDesktopSettings()`와 `setCloseToTray(boolean)`만 추가했다. 응답의 trayAvailable은 현재 유효한 Tray 보유 여부이며 기본 꺼짐이면 false다.

`desktop/lifecycle.cjs`는 실제 Tray 생성과 설정 저장이 모두 성공해야 옵트인을 적용한다. 실패하면 창을 표시하고 메시지를 반환한다. 시작 시 이전 활성 설정으로 트레이를 만들지 못하면 해당 실행만 비활성으로 시작하고 설정 원본은 보존한다. 활성 상태의 닫기는 숨김, 클릭/열기/두번째 실행/알림 클릭은 복원·표시·포커스다. 종료는 app.quit 경로로 통일하며 beforeunload를 무시하지 않는다. 미저장 확인은 부모 창을 가진 native dialog, 기본 취소이며 승인에서만 unload를 허용한다. 자동 시작/자동 업데이트는 없다.

공유 반복 조회는 요청 시작일 부근으로 이동해 오래된 일정을 포함한다. 결과는 조회당 최대400회차이며 데이터 복제를 저장하지 않는다. 현재42일 달력·3일 알림 조회 범위에 충분하다.
