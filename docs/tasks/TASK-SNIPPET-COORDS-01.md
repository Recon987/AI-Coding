## 구현 메모
- 계약 변경: `dd_to_dms(value, axis="lat")` → `(도, 분, 초, 반구)`, 반구는 N·S·E·W. `dms_to_dd(도, 분, 초, 반구)` → 부호 있는 십진도. 부호를 도에 싣지 않으므로 0도(남위·서경 1도 미만)에서도 반구가 남는다. 앱의 좌표 입력(`decimalToDms`의 hemisphere)과 같은 규칙이라 설명의 "순찰 기록의 좌표 입력과 같은 규칙"이 사실이 됐다.
- 경계: 위도 ±90·경도 ±180 밖은 ValueError, 초를 0.01″ 단위로 한 번만 반올림한 뒤 분·도로 나눠 59.999″ 같은 자리올림 문제가 없음(37.9999999 → 38°0′0″N), 분·초 범위 검사.
- 적용 범위: 예제는 빈 보관함에서 '예제 3개 넣기'를 누를 때만 들어간다. 이미 넣은 사용자의 예제(같은 ID)는 자동으로 바꾸지 않는다(검사로 고정). 예전 예제를 쓰는 사용자는 그 스니펫을 지우고 다시 넣지 않는 한 그대로다 — 필요하면 내용을 직접 고치도록 안내가 필요하다(사용자 판단).
- 검사: tests/ax-desk.test.cjs에서 Python 3.9+로 예제를 실제 실행해 13개 값(±0.5, ±38.119444, 0, -1″, 37.9999999, ±90, 경도 -0.5·±180·-127.123456) 왕복·반구·자리올림과 앱 변환 일치, 범위 밖 거부를 확인. Python이 없는 환경이면 건너뜀으로 표시(성공으로 세지 않음). Codex 감사 SNIP-01 통과.
