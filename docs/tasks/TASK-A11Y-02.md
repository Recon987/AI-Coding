### 검증 중 발견 보완 (2026-10-18, Claude)

Codex가 TASK-REVIEW-A11Y-02 검증 중 찾은 두 결함(Codex 환경 시작 실패로 보완이 미푸시 상태)을 구현자 Claude가 원 브랜치에서 같은 설계로 고쳤다.
1. 같은 문구로 연속 저장하면 상태가 바뀌지 않아 화면낭독기가 다시 읽지 않고 8초 타이머도 첫 저장 기준으로 끝났다 → 알림 상태를 {message, sequence}로, 상시 status 안 메시지에 sequence를 key로 써 새로 안내, 타이머 재시작.
2. 닫기(×) 버튼이 aria-hidden 영역 안·Tab 제외라 키보드·화면낭독기로 닫을 수 없었다 → 문구만 aria-hidden(상시 status가 읽음), 버튼은 '알림 닫기' 이름으로 Tab 순서에 두고, 버튼에 포커스가 있는 동안 타이머 정지, 닫으면 직전 위치로 포커스 복귀.

### Windows 실행 39152335566 실패와 수정 (2026-10-18, Claude)

### 원인 확정과 앱 수정 (2026-10-18, Claude)

7bc5cdd Windows 실행 39153133657의 낭독 영역 기록: 1번 알림 0.588초, 2번 알림 5.610초, 지워짐 8.610초 = 1번 알림 타이머(0.61초 시작 + 8초). 2번 알림이 화면에 반영된 직후, React가 이전 타이머를 정리(효과 정리)하기 전 짧은 틈에 옛 타이머가 실행되어 새 알림을 지웠다. 느린 Windows에서 이 틈이 드러났다. **검사만의 문제가 아니라 앱의 경쟁 조건**(첫 알림이 끝나 갈 무렵 다시 저장하면 새 알림이 곧바로 사라질 수 있음)이므로 src/main.tsx를 고쳤다: 타이머는 자기가 시작된 번호(sequence)의 알림만 지운다. 검사의 시계 정지·정확한 대기·변경 기록은 유지한다.
