# Claude·Gemini 공동 검토 요청서 — 제품 방향 재점검

상태: 전달용 초안. 이 대화에서 두 에이전트에 직접 전송/호출하거나 응답을 받은 상태가 아니다.

## 공통 브리프
사용자는 국립공원공단 업무 전반을 지원하는 범용 업무 수첩을 원한다. 사업·업무·일정·자료 연결, 반복 보고, 인계/공유를 모두 포함한다. 개인 단독 사용부터 가치가 있어야 하고 전문 직무 모듈을 붙이며 내부 API 기반 협업으로 확장할 수 있어야 한다. 최근 작은 보완 위주의 진행에서 제품 도약을 체감하기 어렵다는 것이 이번 요청이다.

참고 한 벌: `docs/product/direction-2026-10-20.md`. 제품 기준 main ea3105e, 사후 검증960d2fb. 원격Claude4c4f521은SECURITY-03진행중으로별도보존. 사용자에게서세범주모두필요하다는답변을받았다. 아래 검토 요청은 신규 코드 구현·기관 API 접속·자동 병합을 승인하지 않는다.

## Claude에게 — 총괄·아키텍처 검토
공통 사업·업무 코어가 AX·순찰·행정·자원보전 흐름을 수용하는지 검토해 달라. SECURITY-03의 체크포인트와 다음 검증을 보존하면서 방향 검토를 진행해 달라.

답변형식:
1. 방향안 수용/수정할 핵심3점(근거경로).
2. 첫 시제품 ‘오늘 → 사업 공간 → 정리/보고’에서 가장 먼저 완주할 흐름1개와 수용기준.
3. 일반사업/업무모델과AX·순찰원본의호환/참조방식, 모듈계약의최소범위.
4. 다음구현카드안최대3장(제목·사용자결과·범위·완료조건·의존만, 아직ready확정하지않음).
5. Gemini/Codex가판단해야할남은쟁점최대3개.

금지: 사용자답변없이새우선순위확정,전면재작성/스키마일괄전환,실제API접속,이번전략에대한승인자를임의기록.

## Gemini에게 — 범용성·제품 경험 검토
위 공통 브리프와 방향안을 기준으로 검토해 달라. 현재 화면이나 시안이 필요하면 총괄에게 구체적으로 지정한다.

답변형식:
1. 시설·자원보전·AX·행정의하루/한주흐름에서빠진업무또는강제로맞춰야하는반례(최대5개,가설표시).
2. ‘회의/전화 → 후속작업 → 사업/자료연결 → 주간실적·인계’의세화면동선과첫사용시빈상태.
3. 공식레퍼런스최대3개에서가져올상호작용과그대로복제하면불편할부분.
4. 범용코어와전문모듈에나눌내용, 첫제품데모에서빼도되는것.
5. 제안지표에대한반론과사용자에게결정받을쟁점.

## Codex가 이어서 할 일
두 모델의 실제 응답을 받으면 하나의 결정표에 합의·차이·결정 주체·영향을 기록한다. 확정된 흐름의 시제품과 자료 계약을 만들고 사용자 검토 후 구현 카드로 나눈다. 안전성을 통과 조건으로 유지하면서 사용자 결과·처리 시간·중복 입력을 측정한다.

## 컨텍스트·검증 비용
공통 브리프·관련 문서 링크·기준 SHA를 한 번 공유하고 후속은 변경점만 전달한다. 문서 검토는 보드·링크 검사, 구현은 변경 위험에 맞는 단위·실제 앱 검사, 출시·병합 단계는 저장소 필수 검사를 수행한다. 필수 검사를 줄이거나 실패를 통과로 기록하지 않는다.
