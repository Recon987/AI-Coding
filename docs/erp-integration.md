# 사무소 근무현황판과 ERP 자료 연결

2026-10-15: 사용자가 ERP 내보내기 열·근무 코드·운영 범위를 **미확인**으로 답변했다. 아래는 구현한 로컬 모델/표준 CSV 계약이며 기관 ERP의 실제 형식으로 간주하지 않는다. 앱은 ERP·외부 API에 접속하지 않는다.

## 현재 가능한 흐름

사무소 현황 → 조직 관리 → 직원 관리 → 거점 관리 → 근무현황 순서로 수동 등록한다. 일별 현황과 월요일 기준 7일 근무표는 같은 원본에서 계산한다. 기본 근무(사무소/휴무/연가/출장/거점)와 당직(없음/주간당직/숙직)을 별도 필드로 보관하여 거점근무+숙직을 함께 표시한다. 미등록은 근무로 추정하지 않는다. 자동 편성·휴가 승인·근태 정산·공용 서버 동기화는 없다.

조직 계층은 parentId로 연결한다. 전체 조직 또는 특정 조직을 선택할 수 있으며 특정 조직 선택은 그 조직의 직원을 표시한다(하위 조직 자동 포함 아님). 여러 사무소의 조직을 등록할 수 있지만, 다른 PC와 자료를 동시에 공유하는 기능은 없다. 비활성 직원은 새 날짜 현황에서 제외하고, 실제 근무 기록이 있는 날짜에는 보존 표시한다.

## 모델과 ERP 매핑 예정 항목

| 로컬 항목 | 현재 필드 | ERP 확인할 내용 |
| --- | --- | --- |
| 조직 | id, code, name, parentId | 조직코드·상위코드·조직명·유효기간 |
| 직원 | id, code, name, organizationId, position, active | 직원번호·성명·소속코드·직위·재직/전출 상태 |
| 거점 | id, code, name, organizationId | 거점코드·명칭·관할 조직 |
| 근무 | id, employeeId, date, workType, duty, baseId, note | 근무일·직원번호·근무 코드·당직 코드·거점 코드·승인/확정 여부 |

내부 UUID는 이름이 바뀌어도 참조를 유지한다. CSV는 조직/직원/거점 코드를 기준으로 추가·갱신하며 근무는 직원+날짜로 갱신한다. 전출 이후 과거 소속을 날짜별로 재현하는 인사 이력은 아직 별도 모델이 없다. 현재 소속을 표시하므로 공식 과거 근태 보고서로 사용하지 않는다.

## 표준 CSV 반입

UTF-8 CSV, 최대 2MB/10,000행. 머리글 순서는 바꿀 수 있으나 아래 열 이름을 모두 포함한다. 선택 값은 빈 칸으로 두고 열은 유지한다. 조직 → 직원/거점 → 근무 순서로 반입한다. 상위 조직은 같은 파일의 뒤 행에 있어도 연결된다.

```csv
code,name,parentCode
PARK,시험 사무소,
FIELD,시험 부서,PARK
```

```csv
code,name,organizationCode,position,active
E001,시험 직원,FIELD,담당,true
```

```csv
code,name,organizationCode
B01,시험 탐방지원센터,PARK
```

```csv
employeeCode,date,workType,duty,baseCode,note
E001,2026-10-15,base,night,B01,교대 인계
```

workType: work / off / leave / trip / base 또는 사무소 근무 / 휴무 / 연가 / 출장 / 거점근무.
duty: none / day / night 또는 없음 / 주간당직 / 숙직. active: true / false.

거점근무에는 baseCode가 필요하며 다른 근무에는 비운다. 같은 파일 안의 중복 코드나 직원/날짜, 잘못된 날짜·소속·거점·상위 순환은 미리보기에서 거부한다. 한 행이라도 오류면 전체 반입을 적용하지 않는다. 미리보기에서는 저장하지 않으며 추가/수정/유지 내역을 확인 후 적용한다. 파일에 없는 기존 자료는 삭제하지 않는다. 최초 50행을 표시하지만 검증·적용은 전체 행을 대상으로 한다.

## 실제 ERP 연결 전 확인

사용자에게는 접속 비밀번호나 실명 명단 대신 내보내기 열 이름, 근무 코드 목록, 같은 날 가능한 근무 조합, 사무소/분소 적용 범위를 요청했다. 확인 후 실제 열→표준 필드 매핑, 코드 변환표, 날짜 기준과 휴가 승인/확정 처리, 수동 수정 충돌 정책을 추가한다. ERP DB 계정을 앱에 넣거나 직접 접속하는 방식은 채택하지 않는다.

현재 CSV 반입은 파일을 변경하기 전에 전체 무결성을 검사한다. 기존 자료와 함께 전체 JSON 백업·복원에 포함되며, v1/v2→v3 형식 전환은 원본 바이트 자동 백업 후 수행한다. 초기 사용자 데이터는 평문이며, 운영 자료 적용 전 기관의 보관 정책에 맞춰야 한다.
