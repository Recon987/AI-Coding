| 무엇을 | 왜 | 어떻게 |
| --- | --- | --- |
| 보호본(마지막 정상본) 만들기 실패를 화면에 경고 | 전에는 시작할 때나 백업 복원 직후 실패하면 로그에만 남아 사용자가 몰랐다 | 시작·복원 때 생긴 경고를 화면이 불러온 뒤 한 번 빨간 알림으로 보여 준다 |

## 2. TASK-PANEL-01 — 역할 다섯 개로 나눠 서로 검토·협의 (10-18)

사용자 요청: "역할을 다섯 개로 나눠서 서로 검토한 후 상의해서 좋은 프로그램으로 개선해 봐".

### 2-1. 진행 방식

| 단계 | 내용 |
| --- | --- |
| 1차 검토 | 다섯 역할이 서로 결과를 보지 않고 따로 검토: ① 현장 직원(업무 적합성) ② 화면 디자인·사용성 ③ 자료 안전·보안 ④ 접근성(키보드·화면낭독기·확대) ⑤ 코드 품질·테스트. 발견 40건 |
| 2차 교차 검토 | 각 역할이 다른 역할의 발견 32건에 찬성/조건부/반대를 달고, 이번에 할 것 5개씩 투표 |
| 합의 | 3표 이상 → 먼저 구현, 2표이면서 조건이 분명 → 다음으로 구현, 나머지는 다음 주기 카드 |
| 구현 | 아래 8가지 |
| 3차 재검토 | 제안했던 역할이 구현 결과를 다시 확인 → 지적 사항 모두 수정 |

반대가 나온 것은 두 가지였다. "목록 버튼을 마우스를 올릴 때만 보이게" 안은 접근성·현장 역할이 반대해 UX 역할이 철회했다. "편집 중 초안을 파일로 따로 저장" 안은 암호화 과제와 겹쳐 보류했다.

전체 원문: [docs/reviews/2026-10-18-panel.md](../reviews/2026-10-18-panel.md)

### 2-3. 3차 재검토에서 고친 것

- 순찰 입력 안내가 실제로 복사한 기록이 아니라 늘 '최근 순찰'을 출처로 보여 주던 문제 → 실제 출처와 실제로 채운 칸만 표시.
- 담당구역에 "3구역"을 적으면 제목이 "3구역구역"이 되던 문제.
- 기본값 기준을 '순찰 일시가 가장 늦은 기록'에서 '마지막으로 추가한 기록'으로 변경(지난 순찰을 늦게 입력하거나 시각을 잘못 넣어도 기본값이 엉키지 않도록). 자료 안전 역할의 2차 조건과 달라 이유를 기록했다.
- 브리핑의 '근무'를 사무소 화면과 같은 '근무·출장'으로, 조치 이름을 한 곳(상수)에서 가져오게.
- 잠김 판정 코드를 한 곳으로 모으고, 시작 시 같은 파일을 두 번 읽던 것을 한 번으로.
- 순찰 빠른 입력 동작을 병합 기준 자동 테스트에 포함.
