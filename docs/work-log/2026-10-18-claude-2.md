## 2. TASK-EDITOR-01 — 편집 창 위쪽을 한 줄로

**왜**: 5개 역할 검토에서 UX 역할이 지적했다. 편집 창 위가 '제목 + 닫기 ×' 줄과 '저장·취소' 줄 두 줄(128px)이라 입력란이 아래로 밀리고, '닫기 ×'와 '취소'가 같은 일을 했다.

**무엇을 바꿨나**

| 전 | 후 |
| --- | --- |
| 제목·닫기 × 줄 + 저장·취소 줄(128px) | 제목·저장·취소 한 줄(68px). 입력란이 60px 위로 |
| 닫기 ×, 취소, Esc 세 가지 | 취소와 Esc 두 가지(같은 확인창을 거침) |
| 키보드로 저장하려면 저장 버튼까지 이동 | Ctrl+Enter로 바로 저장(제목 옆에 'Ctrl+Enter 저장' 안내, 화면낭독기용 단축키 정보) |
| 모든 편집 창 너비 600px | 메모·전화 메모는 480px |
| 양식 출력 창의 실행 버튼이 맨 아래 | 파일로 저장·미리보기 복사·닫기를 위 한 줄로 |

필수 표시·오류를 해당 칸에 연결하는 일과 저장 중 키보드 위치 유지는 카드 크기 규칙에 따라 **TASK-EDITOR-02**로 나눴다.

**검사**: 단위 89/89, 실제 앱 검사 8종 통과(편집 창에 닫기 버튼이 없는지, 저장·취소가 머리 줄에 있는지, 글 상자 안에서도 Ctrl+Enter로 저장되는지 확인 추가), 화면 배치 142 실패 0.

## 3. TASK-EDITOR-02 — 입력 오류 안내와 저장 중 키보드 위치

**왜**: 접근성 역할 지적(A2·A3). 오류가 창 맨 위에 한 줄로만 나와 어느 칸이 틀렸는지 연결되지 않았고, 좌표가 틀리면 저장 버튼이 이유 없이 잠겼다. 저장하는 동안 버튼이 잠기면 키보드 위치가 화면 맨 처음으로 튀었다.

| 전 | 후 |
| --- | --- |
| 필수 칸은 안내문에만 적힘 | 필수 칸 레이블 옆에 흐린 '필수' 표시 |
| 통제 종료일·반복 종료일 오류가 창 위나 아래 한 줄 | 해당 칸 바로 아래 빨간 글씨, 칸 테두리 빨강, 화면낭독기가 칸과 함께 읽음 |
| 좌표가 틀리면 저장 버튼이 잠김(이유 없음, 키보드로 닿지도 않음) | 버튼은 그대로, 누르면 "표시된 칸을 고친 뒤 저장하세요" 안내와 함께 틀린 칸으로 이동 |
| 저장 중 '처리 완료' 등을 누르면 키보드 위치가 맨 처음으로 | 같은 버튼에 그대로 남음(이름이 '미처리로 변경'으로 바뀌어도) |
| 저장 중 왼쪽 메뉴·사무소 탭이 잠김 | 잠그지 않고, 저장 중에는 동작만 무시 |

남은 한계: 빈 필수 칸은 아직 브라우저 기본 말풍선으로 알린다. 홈 브리핑 화면의 완료 버튼 등은 이번 범위에서 바꾸지 않았다.

**검사**: 단위 89/89, 실제 앱 검사 8종(키보드 토글 뒤 포커스 유지, 통제 종료일 오류 연결, 좌표 오류 시 저장 안 됨·칸 이동 확인 추가), 화면 배치 142 실패 0, 업무 흐름 11/11.

## 5. TASK-DATES-01 — 날짜 계산을 한 곳으로

**왜**: 코드 품질 역할 지적(C2). '이번 주(월~일)', '하루 앞뒤', '이번 달·최근 30일' 계산이 브리핑·사무소·달력·양식 출력·단속 집계 다섯 화면에 따로 들어 있었고, 계산 기준 시각도 달라 연말·월말·시간대 경계에서 한 곳만 틀릴 위험이 있었다.

**무엇을**

- 시간대에 기대던 기존 테스트 자료 2곳을 고쳐, 단위 테스트가 서울·UTC·미국 서부·태평양 양 끝 5개 시간대 모두에서 통과한다(전에는 미국 서부에서 실패).

**검사**: 단위 91개(5개 시간대), 실제 앱 검사 8개 진입점, 화면 배치 142 실패 0, 업무 흐름 11/11.

**남은 한계**: 실제 Windows 고대비 테마와 화면낭독기(NVDA)는 기관 PC에서 확인해야 한다(자동 검사는 고대비 흉내로만 확인).


## 10. Codex 검증 중 발견한 알림 결함 2건 보완 (A11Y-02)

Codex가 A11Y-02를 검증하다가 결함 2건을 찾았지만, Codex 실행 환경이 시작에 실패해 고친 내용을 올리지 못했다. 둘 다 Claude 구현의 결함이라 Claude가 Codex가 남긴 설계대로 직접 고쳤다.
- 같은 문구("변경 사항을 저장했습니다.")로 연달아 저장하면 두 번째 저장을 화면낭독기가 읽지 않고 알림도 일찍 사라졌다 → 알림마다 일련번호를 붙여 매번 새로 읽고, 8초를 다시 센다.
- 알림의 × 버튼을 키보드·화면낭독기로 쓸 수 없었다 → '알림 닫기' 버튼으로 Tab 이동 가능, 버튼에 있는 동안 알림 유지, 닫으면 원래 작업하던 칸으로 돌아감.
- 새 검사가 고치기 전 코드에서는 실패하고 고친 뒤 통과하는 것을 확인했다. 전체 검사 통과.

Codex 환경의 오류(`exec-server protocol error: failed to query executor configuration capabilities`)는 Codex 쪽 실행 환경 문제라 이 세션에서 고칠 수 없다. 반복되면 서비스 지원에 전달해야 한다.


## 11. Windows에서만 실패한 알림 검사 — 실제 경쟁 조건이었음

알림 보완(f9a8fdb) 뒤 새 검사가 Windows에서만 계속 실패했다. 처음에는 '검사 시간 여유 부족'으로 잘못 진단해 두 번 헛수정을 했고, 그다음 검사가 결과를 기록하게 바꿔 원인을 확정했다. 두 번째 알림이 뜬 직후, 앱이 첫 알림의 8초 타이머를 정리하기 전 아주 짧은 틈에 그 타이머가 실행되어 새 알림을 지웠다. 실제 사용 중에도 생길 수 있는 문제라 앱을 고쳤다(타이머는 자기 알림만 지움).

## 12. TASK-LIST-02 — 목록 행 버튼 위치·모양 통일 (10-19)

사용자 요청: "이어서 LIST-02 진행해". 5개 역할 검토에서 화면 디자인 역할이 지적한 U2(버튼이 행마다 위치·모양이 달라 훑어보기 어렵고 행이 높다)를 처리했다.

| 무엇을 | 왜 | 어떻게 |
| --- | --- | --- |
| 버튼을 행 오른쪽 같은 줄에, 모든 행에서 세로로 맞춤 | 버튼 줄이 내용 아래에 따로 있어 행이 높고 화면에 보이는 기록 수가 적었다 | 목록을 '내용 \| 버튼' 2열로 나누고 버튼 열 너비를 모든 행이 공유(CSS subgrid). 좁은 화면(1100px 이하)은 전처럼 아래로 |
| 버튼 모양 규칙 | '첫 번째 버튼은 테두리'라서 통제 화면은 '수정'이, 다른 화면은 '처리 완료'가 강조되는 등 뜻이 섞였다 | 상태를 바꾸는 버튼(처리 완료·조치 완료·오늘 해제·인수인계로 연결)만 테두리, 수정·보조는 글자, 삭제는 빨간 글자. 통제 화면은 '오늘 해제'를 앞으로 |

- **자료 관리 → 공휴일 관리**: 임시공휴일처럼 미리 알 수 없는 날을 직접 등록하거나, `2030-06-05,지방선거일`처럼 여러 줄을 붙여 넣어 한 번에 등록하고, 삭제할 수 있다. 한 줄이라도 틀리면 아무것도 등록하지 않고 틀린 줄을 알려 준다. 이미 있는 날짜는 건너뛴다. 인터넷에서 가져오지 않고 이 PC 자료에만 저장한다.
- 음력 공휴일 표(2025~2035년) 밖의 해를 달력에서 보면 "음력 공휴일이 표에 없습니다" 안내가 나온다.

## 20. TASK-BACKUP-02 — 복원 보호본 최근 5개만 보관 (10-19)

사용자 요청: "이어서 BACKUP-02 진행해".

**왜**: 백업에서 복원할 때마다 "복원 전 자료" 사본(`workdesk.json.before-restore-<시각>.json`, 최대 20MB)이 생기고 지워지지 않았다. 평문 개인정보(직원 이름 등)가 계속 쌓였다.

**바뀐 점**
- 복원 전 사본은 **최근 5개만** 남긴다. 오래된 것부터 지운다.
- 지우기 전에 알린다: 복원 확인창에 "복원 전 보호본은 최근 5개만 보관합니다"와, 이번 복원으로 지워질 사본의 개수·날짜가 나온다. 필요하면 취소하고 먼저 다른 곳에 복사할 수 있다.
- 지우는 것은 복원이 성공한 **뒤**다. 지우지 못해도 복원은 그대로이고 화면에 경고만 한 번 나온다.
- 예전 형식(v1/v2) 전환 백업, 손상본, 마지막 정상본, 직접 만든 백업 파일은 지우지 않는다.
- 앱 안내 화면과 README 문구를 고쳤다.

검사: 단위 116개(새 2개), 실제 앱 검사 12종(복원 검사에 확인창 안내·5개 유지·가장 오래된 것만 정리 추가, 미국 시간대에서도 통과), 화면 검사 150개 실패 0, 업무 과업 11개.

## 21. Codex 자료 안전성 감사 DS-01 — 복원 뒤 정리 오류가 복원을 되돌리던 결함 수정 (10-19)

사용자 전달(Gemini 지시): Codex가 PR #10에서 찾은 DS-01을 확인·수정.

**무엇이 문제였나**: 백업 복원이 끝나 파일이 이미 바뀐 뒤, 오래된 복원 보호본을 정리하려고 폴더 목록을 읽다가 오류(권한 등)가 나면 앱이 "복원 실패"로 처리했다. 그래서 화면은 복원 전 자료를 그대로 보여 주고, 그 상태에서 메모 하나만 저장해도 **복원한 자료가 복원 전 자료로 덮어써졌다**. BACKUP-02(20장)에서 들어간 결함이다. 선택한 백업 파일 자체는 남아 있어 다시 복원할 수는 있었다.

**어떻게 고쳤나 (두 겹)**
1. 복원이 확정된 뒤의 정리 단계 오류는 모두 "경고"로만 알리고, 복원된 자료를 화면에 돌려준다. 정리하지 못한 보호본은 그대로 둔다. 복원 확인창 전에 목록을 읽지 못하면 복원은 그대로 하되 이번에는 정리하지 않는다고 안내한다. 확정 전 오류(백업 파일이 잘못됨, 보호본을 못 씀 등)는 지금처럼 실패로 처리하고 원래 파일을 지킨다.
2. 복원이 어떤 이유로든 실패하면 화면이 디스크의 현재 자료를 다시 읽는다. 화면에 남은 옛 자료가 다음 저장으로 디스크를 덮을 수 없다.
- 두 겹 중 하나만 있어도 막히는 것을 확인했다.
