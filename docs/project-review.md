# 프로젝트 검토 및 국립공원 업무 적용 — 2026-10-15

## 판단

국립공원 현장의 개인 업무 도구는 기록을 작성하는 것뿐 아니라 다음 조치를 놓치지 않게 해야 한다. 그래서 이번 v0.2의 중심은 `순찰 기록 → 인수인계 → 마감·알림 → 완료 이력`이다. 공식 기관 서식을 받지 않은 상태이므로 이를 개인 기록 기능으로 제공하며 결재 문서나 공단 공식 대장으로 표현하지 않는다.

기후노트의 오프라인 사용·빠른 접근 방식은 참고했지만, 현재 저장소의 Electron/React 구현을 유지해 독립 개발한다. 업로드된 원본 코드를 기존 저장소에 복사하거나 번들에 넣지 않는다. 원본을 부분적으로 가져오면 구현과 라이선스, 암호화·백업 호환성, Windows 검증을 함께 이어받아야 한다. 전체 원본과 검증 환경 없이 섞기보다 현재 앱에서 검증 가능한 업무 흐름을 완성한다.

## 검토 근거와 한계

현재 저장소의 화면·IPC·저장/백업·검증 스크립트 및 제공된 기후노트 README, 상세 README, main.py, ui_main.py, database.py, security.py, 미니앱 등록/화면, AGENTS.md, ARCHITECTURE.md, lockfile, GPL LICENSE를 검토했다. 기후노트의 나머지 모듈·리소스·Windows 전체 실행은 검토하지 못했다. 문서의 테스트 수는 이 프로젝트의 실행 증빙으로 사용하지 않는다.

참고 코드에서 확인한 것은 날짜 기반 일정, 선택형 도구 실행, SQLite/백업 체계, 외부 law.go.kr 링크를 여는 법령 검색이다. 따라서 기관용 법령 오프라인 검색과 시간별 알림은 별도 기능이다. 참고 security.py의 문자열 접두 경로 검사는 이름이 유사한 형제 폴더를 허용하는 경우를 로컬 경로 비교로 재현했다. 기기 ID 기반 키와 4자리 PIN 방식의 설명은 우리 앱의 암호화 설계로 채택하지 않았다. 이것은 원본 앱 전체에 대한 보안 감사나 실제 악용 가능성 판정은 아니다.

## v0.1에서 개선한 점

- 기능이 한 파일에 밀집돼 있던 화면을 순찰·업무·일정·메모·브리핑 단위로 나눴다.
- Electron과 브라우저가 동일한 데이터 검증·달력·브리핑 계산 모듈을 사용한다.
- 단순 날짜순 일정 목록을 월간 달력으로 바꾸고 순찰/인계/제출의 원본을 직접 표시한다.
- 모든 저장과 복원에 연결 ID·자료 버전·완료 일시·알림 범위를 검증한다.
- v1 원본 백업 후 v2로 전환하며 반복 실행 때 백업을 덮지 않는다.
- 저장 실패 시 화면만 성공 상태가 되지 않도록 저장 성공 후 화면을 갱신한다. 저장·복원 중 중복 조작을 막는다.
- 순찰을 삭제해도 연결된 인계 내용은 남고 연결만 해제한다. 인계의 자료는 생성 시점 요약이며 이후 순찰 내용을 자동 덮어쓰지 않는다.
- Windows 자동 빌드로 기관 PC의 npm 인증서·설치 부담을 줄일 전달 경로를 준비했다.

## 운영 전 남은 사항

저장·백업은 현재 평문이며 개인용 개발 시제품이다. Electron safeStorage/Windows 계정 보호와 암호 기반 이동 백업 등을 별도 위협 모델로 설계해야 한다. PIN UI만 추가하는 것으로 저장 보호가 완료되지는 않는다. 실제 민원인 자료를 쓰기 전에 이 작업을 완료해야 한다.

알림은 앱 실행 중에만 제공한다. v0.6에서 기본 꺼짐인 트레이 상주와 절전 복귀 24시간 점검을 추가했다. 실제 Windows 토스트와 절전은 실기기 확인 대상으로 남긴다. 현재 기록은 사용자 입력이며 공식 근무현황·공적 업무 이행을 증명하지 않는다.

개발용 패키징 의존성의 기존 moderate 경고는 별도 공급망 검토 대상이다. 패키지 서명·TLS·해시 검증을 끄는 해결책은 적용하지 않는다. Windows 설치·알림·높은 DPI·다중 모니터는 실제 배포 PC에서 확인해야 한다.
