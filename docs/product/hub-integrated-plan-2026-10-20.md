## 1. 제품 목표와 첫 결과

**가볍게 기록하고, 사업·업무·근거를 필요할 때 연결하며, 같은 원본으로 실적과 인계를 정리하는 공단 업무 허브.**

첫 데모는 ‘메모/전화/회의 → 후속 작업 → 사업·근거 연결 → 오늘/달력에서 기한 관리 → 완료 → 기간 실적·인계 초안’이다. 단발 할 일은 사업 없이 쓸 수 있다. 범용 코어 위에 AX·순찰 같은 전문 기능을 더한다.

## 2. 단일 결정표

‘채택’은 이번 Codex 통합안의 선택이며 작성자 전체의 승인을 뜻하지 않는다.

## 3. 자료·상태 계약

### 소속과 출처

새 `workItems / projects / meetings / resources / links`는 제안 명칭이다. 정확한 타입·검증은 B1 계약에서 확정한다.

- WorkItem은 사업 0~1개에 소속된다. `projectId`를 유일한 기준으로 두고 같은 소속을 partOf 링크로 중복 저장하지 않는다. 이 ID는 공통 projects만 가리키며 AX ID와 혼용하지 않는다.
- **회의·메모·전화·순찰은 여러 사업을 아우를 수 있다.** 회의의 단일 projectId 대신 links로 소속을 표현한다. Claude의 Meeting.projectId 안을 Gemini 반례에 맞춰 수정 권고한다. 회의 원본을 복사하지 않아도 후속 작업을 서로 다른 사업에 둘 수 있다.
- followUp은 출처→일반 작업, partOf는 기존 기록/회의→사업, evidence는 업무 기록/사업→근거 자료다. 허용 타입 쌍·중복·자기 참조·끊긴 참조 규칙을 표로 확정한다.
- 같은 근거를 여러 사업에서 연결한다. 기존 폴더·스니펫을 강제로 복사·이관하지 않는다.
- AX 예산·권역·전문 단계는 AX 원본에서 읽는다. 공통 사업 상태는 Project가 관리한다. 겹치는 제목·기한·단계의 표시/편집 원본을 정하고 자동 양방향 동기화는 하지 않는다. 모듈 계약은 한 사업에 여러 전문 기능이 기여할 수 있도록 설계한다.

### 상태와 삭제

출처의 제목·본문은 후속 작업을 만드는 초안에 채운다. 저장 뒤에는 각 기록이 독립 수명을 가지며, 후속 작업에서 출처로 돌아갈 수 있다. 원문을 임의로 요약하거나 공식 문구처럼 가공하지 않는다.

후속 작업 완료가 원본 전화 회신·인계·사업까지 자동 완료시키지 않는다. ‘후속 N개 중 M개 완료’를 파생 표시한다. 한 후속의 완료를 전체 완료로 오인하게 하지 않는다.

모듈 숨김은 자료·연결 삭제나 권한 차단이 아니다. 완료한 사업에 사후 작업을 연결해도 사업 상태는 유지한다. 사업 삭제 시 작업은 사업 없음으로 남고 회의·자료 원본은 유지한다. 영향과 제거할 관계를 확인창에 표시한다.

출처가 삭제돼도 후속 본문은 남긴다. 끊긴 참조는 삭제됨으로 표시하고 자동 대체하지 않는다. 구판에서 원본을 수정·삭제한 뒤에도 같은 정책을 적용한다. 별도 이력 없이 삭제 전 내용을 복원한다고 약속하지 않는다.

### 기한·호환·보고

- 기한 없음/날짜만/정확한 일시를 구분한다. 날짜만 있는 작업은 해당 현지 날짜가 끝나기 전에 경과로 표시하지 않는다. 자동 자정 알림을 만들지 않으며 알림 시각·규칙은 명시적으로 정한다.
- ‘새 항목이 남는다’와 ‘모든 구판 혼용에서 업무 의미가 보존된다’를 구분한다. 판독 수준 숫자를 미리 고정하지 않고 SECURITY 검증 후 실제 기준의 봉투/내용 호환을 각각 검사한다. 기존 열거값·의미 변경 시 판독 수준을 재평가한다.
- 기간 완료 작업·회의·순찰처럼 근거 날짜가 있는 기록과 현재 미해결 상태를 구분한다. 기록일이 없는 메모를 작성 시점의 실적으로 추정하지 않는다. 과거 AX 집행률·상태는 이력이 없으면 계산하지 않는다.
- 첫 초안은 현재 자료 기반이며 확정된 역사적 보고서가 아님을 표시한다. 기본 주간 범위는 월요일~일요일로 통일하고 변경할 수 있게 한다. Gemini 예시의 월~금/월~일 혼용과 금주 날짜의 차주 분류는 그대로 따르지 않는다.
- 첫 미리보기는 원본 포함/제외·재생성·복사·TXT/MD 저장을 제공한다. 직접 문서 편집·서식 빌더는 후속이다. 원본 메모 본문과 실제 파일 경로의 출력 포함은 기본 꺼짐으로 둔다.

## 4. 세 화면의 첫 범위

| 화면 | 핵심 경험 | 뒤로 미룰 것 |
| --- | --- | --- |
| 오늘의 업무 | 상태 띠, 제목 한 줄 등록, 통합 작업 목록, 일정, 최근 메모의 후속 만들기 | 만능 입력창·OS 전역 단축키 |
| 사업 공간 | 사업 목록/개요, 작업·회의·출처·근거, AX 정보 기여, 완료 사업 검색 | 간트·다단계 작업·모든 직무 템플릿 |
| 정리·보고 | 기간/사업/일반 업무 범위, 원본 선택, 출처 있는 초안, 복사/TXT/MD | HWP/XLSX 생성·문서 에디터·이력 없는 성과 추정 |

시설·자원보전·AX·행정 네 시나리오는 같은 코어를 검증하는 자료다. 생물종 기록·시설 이력 등 새 전문 모델을 첫 묶음에 모두 넣지는 않는다. 기한 없는 메모와 기존 메모 열람 진입점은 유지한다.

## 5. 첫 구현 묶음 초안 B1~B3

**구현 카드 파일·ready 확정·코드 착수는 아직 없다.** 하나의 제품 목표를 아래 세 단계로 나눈다. 이미 받은 두 응답을 다시 전부 작성시키지 않고 이 계약을 기준으로 시제품·구현·종단 검증을 진행한다.

### B1 — 기록을 바로 할 일로

사업 없는 일반 작업, 제목 한 줄 등록, 메모·전화의 후속 만들기, 출처 복귀, 완료·기한과 오늘/달력 반영. 기존 인계·제출은 읽기 어댑터로 함께 보인다. 회의는 다중 사업 연결이 가능한 최소 기록부터 정의하고 복잡한 에디터는 미룬다.

완료 기준:
- 사업·근거·기한 없이 제목 필수 1개로 등록한다.
- 같은 출처에서 후속을 여러 개 만들고 개별 완료한다. 원본 내용 재입력 0, 출처로 1행동에 이동한다.
- 기존 인계·제출 동작을 보존하고 기한·알림·완료 취소 계약을 검증한다.
- 지원 구판 보존·끊긴 참조·암호 저장/백업 회귀를 포함한다.
- 작업·연결·메모가 섞인 10,000건 조건에서 시작/검색/저장·파일 크기를 측정한다. 조건과 합격선을 구분한다.

### B2 — 사업에 맥락 모으기

일반 사업 공간, 기존 AX의 명시적 연결, 업무 소속, 여러 사업을 아우르는 회의/출처, 독립 근거 자료 N:M 연결, 파일 부재 표시·경로 재지정. 완료 사업의 사후 업무와 모듈 숨김을 검증한다. 관리형 첨부 복사는 미룬다.

완료 기준:
- 사업 선택 후 별도 전체 화면 왕복 없이 작업·회의·근거를 조회한다.
- 공통·전문 상태의 원본과 편집 위치가 명확하다.
- 하나의 근거를 두 사업에서 재사용하고 완료 사업에 사후 작업을 연결한다.
- 사업 삭제가 원본 작업·회의·자료를 삭제하지 않는다.

### B3 — 같은 기록으로 보고·인계 끝내기

현재 자료 기반 주간 실적·차기 계획·인계 초안, 기간/사업/일반 업무 범위, 원본 포함 선택, 출처 이동, 복사·TXT/MD. 기존 양식과 보고 출력은 보존한다.

완료 기준:
- 핵심 흐름을 네 직무의 가상 자료로 끝까지 완주한다.
- 금주/차주·기간 밖 날짜를 올바르게 분류한다.
- 일반 작업과 기존 인계를 관계만으로 중복 집계하지 않는다.
- 사실 항목은 원본 Ref를 가지며, 근거 없는 항목을 사실처럼 꾸미지 않는다.
- 원본 메모 본문·실제 파일 경로 출력은 명시적 선택으로 둔다.

## 6. 수용 목표의 측정 규칙

- Gemini의 5초·2클릭·3클릭은 목표이며 측정 결과가 아니다. 시작 화면·가상 자료·필수 입력·키보드 사용을 고정한다.
- ‘3클릭 보고’는 정리 화면이 열리고 기본 기간/전체 범위가 정해진 상태의 기본 초안 복사를 측정한다. 맞춤 선택·OS 저장 대화상자는 따로 세고 전체 시간을 숨기지 않는다.
- ‘타이핑 0’은 출처 내용의 재입력 0이다. 기한·사업 등 새로운 판단까지 자동 정답으로 채운다는 의미가 아니다.
- 파일 찾기 0초는 채택하지 않는다. 위치 보기까지 조작 수와 실제 시간을 측정한다.
- 자료 보존·접근성·성능은 통과 조건으로 유지하고 사용자 결과도 함께 평가한다. 문서 단계는 문서 검사, 구현·출시 경계는 저장소 필수 검사를 수행한다.

## 7. 다음 실행과 승인 범위

권고는 B1의 빠른 등록·후속 작업·원본 복귀를 첫 작동 시제품으로 만들고 B2/B3으로 같은 흐름을 완주하는 것이다. 시작 전에 타입별 관계·상태·기한·호환 표와 세 화면의 필수 동작을 한 번 확인한다. 신규 직무 모듈·실제 API·메신저를 이 착수 범위에 묶지 않는다.

Claude에는 이 통합안에서 바뀐 계약만 대조해 B1 카드 최종안을 요청할 수 있다. Gemini에는 새 종합 조사 대신 혼합 목록 동작·다중 사업 회의·보고 포함 선택의 화면 문구를 확인하도록 요청한다. 사용자는 큰 제품 묶음과 B1 착수 범위를 보고 승인할 수 있다.

## 8. 확인 한계

제안 자료·모듈 계약은 아직 구현되지 않았다. Gemini의 직무 [확인] 표시에 출처가 첨부되지 않아 업무 가설로 다뤘으며, 클릭 수·시간 약속도 실측으로 기록하지 않았다. Tasks/normalize의 구판 필드 보존 일반화는 현재 코드와 구분해 보정했다. 이 문서는 두 응답을 입력으로 한 Codex 판단이다. 보안 카드의 검증·병합 상태는 변경하지 않는다.
