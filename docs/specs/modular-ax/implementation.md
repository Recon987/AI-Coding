# 모듈형 플랫폼·AX Desk 구현 보정 명세

사용자 원문 TASK-v0.3-ARCH-MODULAR-01의 기능 목표를 현재 저장소 계약에 맞게 구체화한 구현 준비 문서다. [원문](original.md)은 보존한다. [작업 카드](../../tasks/TASK-ARCH-MODULAR-01.md)의 선행 조건 충족 전 제품 코드를 변경하지 않는다.

## 1. 착수 조건과 기준

- 문서 기준 main: `1474d764d98ba972e58194eb67ddce703150cc00`. 앱 버전은0.8.0, 데이터는이미 `version: 3`이다.
- 후속 통합 대기 코드: Claude `afc3825`/증빙f10b1bc, reader2. Codex [PR #11](https://github.com/Recon987/AI-Coding/pull/11)의 DS-01 승인·4카드 승인과 BK-01/P1·HL-01/P2 반려를 함께 확인한다.
- BK-01(시계 역행 시 새 복원 직전 보호본 삭제)·HL-01(공휴일 한도 오류 안내 누락)의 수정과 독립 재검증, 후속6카드 main 병합이 끝나야 구현한다. 이미완료된 DS-01을 다시 구현하지 않는다.
- 조건 충족 당시의 최신main SHA를 새로 기록하고 사용자 지정 `feat/modular-architecture`를 만든다. Step별 작업은 해당 통합 기준에서 작은 task 브랜치/카드로 나누고 즉시 푸시한다. 현재 체크아웃을 쓰며 별도 worktree를 만들지 않는다.
- 원문의 v0.3은 이번 **개편 명세 식별자**로 사용한다. 현재 앱0.8.0을0.3으로 내리지 않는다. 실제 배포 버전은 릴리스 때 증가시키고 데이터 형식 버전과 분리한다.

## 3. 데이터 계약과 무손실 원칙

기존 version3의 notes·events·calls·folders·patrols·tasks·controls·organizations·employees·bases·assignments를 유지한다. 선행 HOLIDAY-01의 customHolidays, minReader와 모르는 최상위 키도 보존한다. 순찰 좌표·단속 건·후속 업무 연결·반복 회차 완료/제외·근무표·알림 설정을 삭제하거나 초기화하지 않는다.

신규 선택 필드는 `modules`, `axProjects`, `axSnippets`다. UI에서 정규화한 결과와 디스크의 기존 원본을 구분한다. 필드가 없으면 메모리에서 기본값을 계산할 수 있지만 단순 열람으로 기존 JSON을 다시 쓰지 않는다.

- `modules`: enabledModuleIds·moduleOrder·customConfigs. 레지스트리 메타데이터/컴포넌트는 JSON에 저장하지 않는다. 설정 객체를 배열용 collections에 섞지 않는다.
- 알려진 ID만 메뉴에 렌더링한다. 원문의 '유효하지 않은 모듈 ID 무시'는 **렌더링 제외**를 뜻한다. 미래 모듈의 미지원 ID·순서·설정은 임의로 지우지 않고 왕복 보존한다. 잘못된 타입·중복·과도한 길이/개수·예약 키는 저장 전에 거부한다.
- customConfigs는 크기/깊이/키 제한을 가진 JSON 값으로 한정한다. 함수·파일 경로 실행·HTML·IPC 명령으로 해석하지 않는다. 이미 같은 이름의 해석 불가 값이 있으면 덮거나 기본값으로 초기화하지 않고 원본 보존 상태에서 전환을 중단/안내한다.
- axProjects·axSnippets는 각각10,000건 이하, JSON 전체20MB 한도를 계속 적용한다. ID 중복·필수 제목·허용 구분·길이·실제 날짜·유한 숫자를 검증하고 입력 객체를 변경하지 않는다.
- 기존 minReader는 낮추지 않는다. 최상위 필드 추가만으로 reader 상향을 자동 결정하지 않는다. reader2가 미지 항목을 실제 보존하는지 검사하고, 기존 값 의미나 enum을 바꾸어 구버전 오해석이 생기면 READER_VERSION/minReader를 함께 올린다.
- SCHEMA-01 이전 실행 파일은 새 키를 보존한다고 보장할 수 없다. 개편 자료를 구버전 앱과 혼용하지 않는 배포·복구 절차를 검증 문서에 남긴다.

### 백업과 초기화

실제 v1/v2는 기존 `migrateFile`의 바이트 원본 백업과 이름 충돌 회피를 유지한다. 현재 v3를 임의로v2라고 표기하지 않는다. 기존v3를 새 선택 필드와 함께 최초로 저장하기 전에는 충돌하지 않는 `.pre-modular-backup-<시각>.json` 등 명확한 개편 전 보호본을 만든다. 백업 실패 시 원본을 변경하지 않는다. 새 이름은 복원 보호본 정리 규칙에 포함하지 않는다. 시계 역행·충돌과 확정 전/후 오류의 의미는 BK-01·DS-01 수정 계약을 유지한다.

스니펫 예제3개는 GEE Sentinel-2 코드, DD↔DMS 설명/코드, 보고서 작성 프롬프트다. 최초 초기화에서만 넣고 고정 예제 ID/표시로 구분한다. 사용자가 삭제한 빈 목록을 다시 채우지 않는다. 예제가 있다는 이유로 기존 첫 사용 안내가 사라지지 않도록 실제 사용자 기록과 구분한다. 예제 코드는 문자열 자료이며 앱에서 실행하거나 외부망을 호출하지 않는다.

## 4. 내장 모듈 레지스트리와 화면

`AppletDefinition`은 원문 메타데이터를 따른다. `shared/applets.mjs` 같은 순수 모듈에 정의하고, React 컴포넌트 연결은 `src/applets.tsx` 등의 정적 신뢰 맵으로 분리한다. JSON의 componentKey가 임의 import/require/파일 실행에 도달하면 안 된다. 이번 범위는 설치본에 포함된 도구의 선택 표시이며 외부 플러그인 파일·원격 설치·자동 업데이트 엔진은 만들지 않는다.

| 위치 | 구성 | 기존 동작 보존 |
| --- | --- | --- |
| 상단 코어4종 | 업무 브리핑 / 인수인계·제출기한 / 달력 / 업무·전화 메모 | 인수인계·제출기한 및 메모·전화메모는 내부 탭/모드로 각각 접근 |
| 중단 직무 모듈 | 현장 순찰 / 사무소 현황 / AX Desk | 순찰 안에서 탐방로 통제도 접근, 로컬 조직·직원·근무표 유지 |
| 하단 | 모듈 관리 / 바로가기 / 앱 안내·자료 관리 | 기존 폴더 바로가기·백업/복원·공휴일 관리·트레이 설정 접근 유지 |

신규 설치의 기본 활성 모듈은 원문대로 patrols·ax-desk다. office도 레지스트리에 등록해 서랍에서 켤 수 있게 한다. 기존v3에 조직·직원·근무 기록이 있는 설치를 전환할 때는 office도 노출해 기존 사용 경로를 보존하는 호환 기본값을 적용한다. 신규 설치/기존 사무소 자료 보유 설치의 두 경우와 초기 순서를 구현 카드에서 구분해 검사한다. 코어4종은 끌 수 없다. 모듈 순서는 드래그를 강제하지 않고 위/아래 버튼으로 키보드 조작도 지원한다.

기본 운영안에서 모듈Off는 메뉴/전용 홈 영역의 표시 설정이다. 데이터 삭제·권한 제어·기존 알림 취소가 아니다. 이미등록된 일정·업무·마일스톤은 유지하며 기존 참조에서 원본에 접근할 수 있어야 한다. 자료 관리·백업에는 비활성 모듈 자료도 포함한다. 숨김 모듈 기록을 검색/달력에서 열 때의 안내와 진입 경로를 Step B에서 명시하고 검사한다. 사용자에게 의미가 달라지는 알림 중단 정책은 별도 결정 없이 추가하지 않는다.

AppletDrawer는 기존 Sheet/확인창/dirty draft 가드를 재사용한다. 저장 중·실패·읽기 전용에서는 실제 저장 상태와 표시를 맞춘다. 현재 모듈을 끌 때 미저장 초안을 잃지 않고 코어 화면으로 돌아가는 경로를 검사한다. 닫기·Esc·Tab 순서·포커스 복귀·좁은 화면을 포함한다. 기존 Page ID(patrol/controls/handover/submission/notes/calls 등)와 원본 ID를 바로 버리지 않고 새 코어/모듈 경로로 매핑해 검색·브리핑·달력 deep link를 유지한다.

## 5. AX Desk 데이터·행동

### 사업 관리

AxProjectRecord의 id·title·zone·stage·budgetTotal·budgetExecuted·manager·partner·nextMilestone·risks·notes·updatedAt를 유지한다. 권역은 본사/서부/북부/연구원·보전원/기타를 빠짐없이 필터링한다. 단계는 기획·발주/계약·수행/실증·검수/완료다.

- 금액은 **천원** 단위를 입력·표시·보고서에서 일관되게 사용한다. 유한한0 이상의 안전한 숫자로 검증한다. 집행액이 총액을 넘는 실제 현황을 임의로100%로 정규화하거나 지우지 않는다.
- 총액0은 나눗셈하지 않고 미편성/예산 미등록으로 표시한다. 초과 집행은 수치와 경고로 보여 주고 막대만 표현 범위에 제한한다. 단계와 예산 집행률을 동일한 진행률로 취급하지 않는다.
- 자유 문장 nextMilestone에 추가로 `nextMilestoneDate: YYYY-MM-DD | null`을 둔다. 날짜가 없으면 임의 추출하지 않는다. 날짜가 있는 사업의 달력·브리핑 항목은 axProjects 원본에서 파생하고 events/tasks에 복제하지 않는다. 알림을 추가할 때도 같은 원본 참조와 중복 방지 계약을 사용한다.
- 등록·수정·삭제 확인·검색·권역/단계 필터·정렬·재실행 보존을 제공한다. 예산을 공식 ERP 집행 자료라고 표현하지 않는다.

### 스니펫 보관함

AxSnippetRecord의 GEE/Python/Prompt/Policy 분류·태그·내용·설명·updatedAt를 검증한다. 이름뿐 아니라 태그·설명·본문도 검색하고 원클릭 복사 성공/실패를 안내한다. 코드와 프롬프트는 React의 텍스트로 표시한다. HTML 삽입·스크립트 실행·Python/GEE 실행 기능은 추가하지 않는다. 큰 코드/한글·따옴표·개행도 저장/복사 후 동일한지 확인한다.

### 보고서 초안

등록 사업을 선택하면 제공된4개 절(사업개요·추진배경·추진실적·향후계획)의 순수 템플릿 함수로 초안을 만든다. 온라인 AI 호출이 아니다. 등록되지 않은 성과·수치·법령·기관 확정 사실을 생성하지 않고 `[작성 필요]`를 표시한다. 실제 공단 공식 서식이 제공되기 전에는 '보고서 초안/추천 구조'로 안내한다.

복사는 기존 클립보드 API를 사용한다. TXT/MD 저장은 명시적 `export-ax-report` IPC 후보로 한정한다. renderer는 사업ID·허용 형식만 전달하고 main이 현재 저장 자료로 본문/안전한 파일명을 다시 만든다. 일반 파일 쓰기나 임의 IPC는 노출하지 않는다. 미리보기와 내보내기는 같은 원본/템플릿 함수를 쓴다.

## 6. Small Atomic Steps와 수용 검사

### Step A — 모델·백업

AppletDefinition·ModuleSettings·AX 타입과 순수 레지스트리/검증을 추가하고 shared/model.mjs·d.mts 및src/types.ts를 같은 계약으로 맞춘다. AX 계산/초안은 shared/ax.mjs 등 독립 순수 모듈로 분리할 수 있다. 기존normalize·저장 계약에 연결한다.

최소 다음 회귀를 포함해10건 이상을 추가한다: ①v1 원본/변환, ②v2 원본/변환, ③기존v3 바이트/필드/참조 보존, ④minReader·미지 키 왕복, ⑤백업 실패·충돌·시계 역행, ⑥모듈ID/순서/설정 검증 및 미지원ID 보존, ⑦AX필수값/중복/구분 검증, ⑧금액0·음수·NaN·초과 집행 표현, ⑨스니펫 태그/개행/크기, ⑩20MB·10,000건, ⑪예제 재주입 방지. 모듈 정의/설정 객체가 기존 배열 집계나 첫 사용 판정을 깨뜨리지 않는지도 확인한다.

`npm test`·기존 `test:desktop`을 통과시키고 카드의 재개 위치·인터페이스·정확한 해시를 커밋·푸시한다. 실패 상태를 통과로 기록하지 않는다.

### Step B — 모듈 관리·메뉴

AppletDrawer·동적 메뉴·순서·코어4종 내부 모드·기존 기능 매핑을 구현한다. 실제 변경 대상은 main.tsx·분리한 레지스트리/라우팅·ui.tsx·스타일·타입·검색 연결이다.

실제 앱에서 순찰Off→사라짐→On→복구, 순서 저장/재실행, 모든 모듈Off여도 코어4종 사용, 통제/사무소/바로가기·deep link 보존, 현재 모듈Off/dirty draft/저장 실패/읽기 전용, 숨김 모듈 자료 보존·기존 알림 유지·키보드/확대를 확인한다. 기존 검사를 새 진입 경로에 맞게 갱신하되 원래 검증하는 업무 결과를 생략하지 않는다. 전체 검사 후 체크포인트를 푸시한다.

### Step C — AX Desk

사업 CRUD/필터/집행률 → 스니펫 CRUD/검색/복사 → 보고서 초안/내보내기 → 마일스톤 원본 파생 순으로 작은 체크포인트를 나눈다. 각각 tests에 연결하고 즉시 푸시한다. AX 사업 저장 후 브리핑과 달력에 정확히1개 파생 항목이 나타나고 수정·삭제·모듈Off 후에도 명시한 정책과 일치하는지 확인한다.

최종 `npm test`, `npm run test:desktop`, 화면/업무 흐름 검사와 외부 요청0, Windows 소스·패키지 검사를 완료한다. 기존v1/v2/v3 및 reader2 자료의 백업/복원·재실행도 포함한다. 구현자가 아닌 검증자의 승인 후 통합하며 docs/handoff.md·validation.md·README와 GEMINI_HANDOFF_PACKET을 갱신한다.
